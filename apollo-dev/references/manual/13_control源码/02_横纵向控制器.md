## 0. 一句话作用

四个控制器是 control 链路真正算数的地方：横向（`LatController`/`LatPlusController`）用**动力学自行车模型 + 离散 LQR** 算方向盘百分比；纵向（`LonController`/`LonPlusController`）用**站-速双环 PID + 标定表反查**算油门/刹车百分比。plus 版在算法骨架上与非 plus 同源，多出的是**工况分档参数**（`params_pipeline` + 多份 `*_param.pb.txt`）与一批安全/补偿工具。框架侧（基类、pipeline、conf 定位）见 `03_control_task框架与controllers清单.md`，组件与数据流见 `01_control_component与数据流.md`。本机生效 pipeline 用的是**两个 plus 版**（另加 demo/antislip/debug 三个 task）。

## 2. 算法骨架

### 2.1 横向：LQR（lat_controller.cc，每 10 ms 一遍）

1. `UpdateState`（655–709）：把车辆状态从后轴中心换算到质心（`ComputeCOMPosition(lr_)`，:666）→ `ComputeLateralErrors` 填 debug → 装状态向量：`matrix_state_(0,0)=lateral_error`、`(1,0)=lateral_error_rate`、`(2,0)=heading_error`、`(3,0)=heading_error_rate`（680–684）；开了 `enable_look_ahead_back_control` 则 0/2 位换成 `*_feedback` 版（676–682）；`preview_window_>0` 时逐个预瞄点算横向偏差填到 `basic_state_size_+i`（687–708）。
2. `UpdateMatrix`（711–732）：A 的 1/3 行按 `1/v` 更新（`v` 有 `minimum_speed_protection_`=0.1 兜底，倒挡且 `reverse_use_dynamic_model=false` 时换运动学式并取 `-0.1` 兜底）；用 **Tustin 双线性离散**：`Ad = (I − ts/2·A)⁻¹ (I + ts/2·A)`（730–731）。
3. `UpdateMatrixCompound`（734–745）：把 Ad/Bd 塞进带 preview 的增广矩阵 `adc/bdc`。
4. Q 矩阵按挡位换：倒挡用 `reverse_matrix_q`，前进用 `matrix_q`（451–463）。
5. **增益调度**：`FLAGS_enable_gain_scheduler` 为真时 `Q(0,0)`、`Q(2,2)` 各乘一次以 `|v|` 为自变量的 `Interpolation1D` 结果（469–474），再解 LQR；否则直接用 `matrix_q_`。
6. 输出 = 反馈（491–493）+ 前馈（495）+ 可选 leadlag 增广（500–509，低速域或 `enable_feedback_augment_on_high_speed`）+ 可选 MRAC / 最大转角速率限制（`enable_steer_mrac_control`、`enable_maximum_steer_rate_limit`，grep 定位 :531/:542，本轮未展开）。

### 2.2 纵向：站-速双环 PID + 标定表（lon_controller.cc）

1. `ComputeLongitudinalErrors`（:206 调用）算 station/speed/preview 误差 → station 误差按 `station_error_limit` 夹（209–219）。
2. **PID 参数按工况切**（221–263）：倒挡 → `reverse_*_pid_conf`；`|v| ≤ switch_speed` → `station_pid_conf` + `low_speed_pid_conf`；否则 `station_pid_conf` + `high_speed_pid_conf`；任一分支内 `CheckPit::CheckInPit` 为真则整体换 `pit_station_pid_conf`/`pit_speed_pid_conf`。
3. 外环：`station_pid_controller_.Control(station_error_limited, ts)` → `speed_offset`（265–269，可选 leadlag）。
4. 内环：`speed_offset + speed_error` 夹到 `speed_controller_input_limit` → `speed_pid_controller_.Control(...)` = `acceleration_cmd_closeloop`（271–289）；空挡时两环积分清零（297–300）。
5. **pitch 补偿**：`digital_filter_pitch_angle_.Filter(vehicle_state()->pitch())` + `FLAGS_pitch_offset_deg` → `slope_offset_compensation = use_opposite_slope_compensation * GRA_ACC * sin(pitch)`（302–320，NaN 归零）；`acceleration_cmd = 闭环 + preview_acceleration_reference + enable_slope_offset * slope_offset_compensation`（322–325）。
6. **标定表反查**（455–515）：`acceleration_lookup`（倒挡取反）与 `|speed|`（`FLAGS_use_preview_speed_for_table` 决定用 preview 速度还是实车速度）二维插值得 `calibration_value`；`use_acceleration_lookup_limit` 时先按 `max_acceleration + 坡道补偿` 截顶。加速侧 `throttle = max(calibration_value, throttle_lowerbound)`、`brake=0`；减速侧 `brake = max(-calibration_value, brake_lowerbound)`、`throttle=0`。下限 = `max(vehicle_param.throttle/brake_deadzone, conf.throttle/brake_minimum_action)`（455–460）。
7. 其余：`FLAGS_use_vehicle_epb` 下的电子手刹逻辑（517–534）、`IsFullStopLongTerm`/`IsPedestrianStopLongTerm`/`IsStopByDestination`/`GetPathRemain`（.h 110–126 声明）。

## 3. plus 版比非 plus 多了什么

| 维度 | 非 plus | plus（多出的） |
|---|---|---|
| 基类 | `ControlTask` | `ControlTaskExtend` → 拿到 `LoadParamsPipelineConfig`、`VehicleStatusIdentificationUpdate`、`IsForwardModel`/`IsEdgeFollow`/`IsLargeCurvature`/`IsLeftCurvature`/`CheckInPit`/`GetVehicleSpeed`/`LoadCalibrationTable(path,…)`（03 篇已核 control_task_extend.h 78–92） |
| conf | 单份 `conf/controller_conf.pb.txt` | 再加 `conf/params_pipeline.pb.txt` + 10 份 `*_param.pb.txt`；每帧选一份生效 |
| 参数装载 | Init 一次读死 | `LoadParams`（lat .cc 318–337 / lon .cc 139–174）按 `params_declare` 逐份 `GetPluginConfPath<ControlTask>("apollo::control::LatPlusController", "conf/<file>")` 读入 `params_list_`；每帧 `ChooseCurrentParam` + `SetCurrentParam` 拷进 `current_*_conf_`，横向再 `UpdateControlConf` 重算矩阵（lat .cc 442–450） |
| 工况判定（横向，lat .cc 362–420） | 无 | 默认 `public_road_forward_param`；`!IsForwardModel()`→`public_road_backward_param`；大曲率+前进→`public_road_forward_s_turn_param`；`trajectory_type==OPEN_SPACE`→`open_space_forward/backward_param`；`IsEdgeFollow()`→`edge_follow_public_road_forward_param` 或 `…_sl/sr_turn_param`（按曲率左右）；`scenario_plugin_type=="ZONE_COVER"`→`zone_cover_forward/backward_param` |
| 工况判定（纵向，lon .cc 210–266） | 无（只有 switch_speed / pit 分支） | 非 OPEN_SPACE→`public_road_forward_param`；OPEN_SPACE→`open_space_forward/backward_param`；`use_check_pit && CheckInPit(...)`→`pit_forward/backward_param`；OPEN_SPACE 且 `PRECISE_PARKING`→`precise_forward/backward_param`；`ZONE_COVER`→`zone_cover_forward/backward_param` |
| PID 形态 | `PIDController` + 多套 conf（low/high/reverse/pit）硬切 | `PIDPlusController`/`LeadlagPlusController`（.h 178–182）+ `CalcultePidParams(speed, PidPlusConf&)`（.h 157）：conf 里给 `speed_input[]` 与 `kp/ki/kd_speed_gain_output[]`，**增益按速度连续插值**而不是分段换表 |
| 标定表 | 单表，Init 一次建（`FLAGS_calibration_table_file`） | `params_pipeline` 的 `calibration_table_declare` 声明多表 → `calibration_table_list_`；每帧 `ChooseCurrentCalibrationTable` 按 `chassis_->battery_soc_percentage() > battery_threshold` 选 high/normal（lon .cc 285–298），表尺寸变化时才重建插值器（330–350） |
| 横向额外能力（lat_plus_controller.h） | — | `TrajectoryAnalyzerExtend`（216）、`ComputeTrackLateralErrors`（134）、AHC 自动朝向补偿（165–168）、`EnhanceQParamsAlternate` 动态加权（183）、`LateralSafetyCheck`/`ResetLateralSafetyCheck`（169–170）、`UpdateLookForwardPointError`（171）、`CheckContinousErrors`（191）、`ResetComLength[FromTurbulence]`（198–200）、`mass_current_`（230） |
| 纵向额外能力（lon_plus_controller.h） | — | `NewFullStop`/`ResetNewFullStop`（158/160）、`check_slip`（159）+`is_slipping_`（222）、`CheckFinishToElse`（161）、`calculte_speed_enter_stop`（163）、`dec_hold_on_slope_`（221）、`enable_stop_control_`/`acc_control_rate_`（223/225）、openspace 专用油门刹车缓存（243–245） |
| 失败语义 | Init 失败才 return error | **每帧**都可能 return `CONTROL_COMPUTE_ERROR`：`VehicleStatusIdentificationUpdate` 失败（lat 437–440）、`ChooseCurrentParam` 失败（lat 442–445 / lon 336–339）、`ChooseCurrentCalibrationTable` 失败（lon 341–344） |

## 5. 修改与扩展点

1. **只调参（最常用）**：改生效 conf → `/apollo/modules/control/controllers/<pkg>/conf/controller_conf.pb.txt`（软链，写穿到 `profiles/current`，即 `profiles/ARCF_40P`，立即落盘），**重启 control 生效**（conf 只在 Init/每帧读 proto 对象，不热更文件）：`cyber_launch stop … && cyber_launch start /apollo/modules/control/control_component/launch/control.launch`。横向先动 `matrix_q`（4 项）与 `lat_err_speed_gain_output`；纵向先动 `speed_pid_conf.kp/ki` 与 `station_pid_conf.kp`。
2. **换控制器**：编辑 `/apollo/modules/control/control_component/conf/pipeline.pb.txt`（同为 profile 软链），`controller { name: … type: LatController|LatPlusController … }`，顺序即执行顺序；不需重编。
3. **加一个工况档**：在包 `conf/params_pipeline.pb.txt` 增 `params_declare { config_name: "<名>" config_path: "<文件>.pb.txt" }`，同目录放该 `*_param.pb.txt`（全字段，`SetCurrentParam` 是 `CopyFrom` 整份覆盖）；**`config_name` 必须与 `ChooseCurrentParam` 里硬编码的字符串完全一致**（lat .cc 365–408 / lon .cc 214–254），要新工况判据就得改这两个函数（改代码 → 走第 4 条）。

## 6. ⚠️ 本环境注意

- **plus 与非 plus 不要同时进 pipeline**：两者都写 `ControlCommand` 的同一批字段（`steering_target` / `throttle` / `brake`），后者覆盖前者且各自维护独立积分与状态，效果不可预期。**`ControlTaskAgent` 里未见任何互斥/重复类型检查（03 篇已核 agent.cc 33–54 只按顺序实例化），需自行确认 pipeline 内容。**
- **plus 版每帧都可能返回 `CONTROL_COMPUTE_ERROR`，一返回就掐断整条控制链**（03 篇已核 agent.cc 70–72，后续控制器当帧不执行）。最现实的触发点：`ChooseCurrentParam` 选中的 `config_name` **没在 `params_pipeline.pb.txt` 里声明** → `Fail to find lat current param[...]` → 整帧失败。本机横向 `params_pipeline` 只声明 6 档，而 `ChooseCurrentParam` 还能选出 `public_road_backward_param`、`edge_follow_…_sl/sr_turn_param`、`zone_cover_forward/backward_param` 4 类未声明档（对应 `*_param.pb.txt` 文件在 conf 目录里存在、但**没进 pipeline 声明**）→ 倒车 / 沿边大曲率 / ZONE_COVER 场景有整链失败风险。纵向同理（`pit_*`、`precise_*`、`zone_cover_*` 未声明，其中 `pit_*` 因 `use_check_pit=false` 暂不会被选）。**未实车验证，属静态推断，上车前建议先补声明或实测确认。**
- **conf 落点混指**：同一个包里的 conf 一部分指 `profiles/current`、一部分指 `/opt/apollo/neo/share`（横向：`public_road_backward`、`edge_follow_…_sl/sr_turn`、`zone_cover_*` 指 share；纵向：`pit_*`、`precise_*`、`zone_cover_*` 指 share）。改前逐个 `readlink`；改到 share 的文件下次 install 会被覆盖。
- **标定表两版**：出厂 `/opt/apollo/neo/share/modules/control/control_component/conf/calibration_table.pb.txt`（6486 行）≠ 生效 `profiles/current/.../calibration_table.pb.txt`（19802 B，ARCF_40P 车型）。非 plus 版走 `FLAGS_calibration_table_file`；plus 版走 `ControlTaskExtend::LoadCalibrationTable(path,…)`，该实现把路径**硬编码拼在 `/apollo/modules/control/control_component/conf/` 前缀后**（control_task_extend.cc 约 50–61，grep 原文所见、未 read 打开）→ 三张声明表最终都落到同一个生效文件，`ChooseCurrentCalibrationTable` 的电量分档当前**实际无差别**。
- **`---calibration_table_file` 三连字符**（`/apollo/modules/control/control_component/conf/control.conf:6`，grep 所见）：gflags 只认 `--`/`-`，该行大概率不被解析；但 `control_gflags.cc` 里 `DEFINE_string(calibration_table_file, "/apollo/modules/control/control_component/conf/calibration_table.pb.txt", …)`（sed 所见 40–43 行区间）与该行取值**逐字相同**，所以生效与否结果一致 —— **原「是否生效」待核项可降级为无影响**；但如果有人想通过这行改表路径，会静默失败。
- **`matrix_q` 条数必须等于 `4 + preview_window`，且非 plus 版还要求 `reverse_matrix_q` 同长**（lat_controller.cc 233–241，不等即 `CONTROL_COMPUTE_ERROR`）。本机 plus 生效 conf 只有 `matrix_q`（4 项）、**没有 `reverse_matrix_q`** —— plus 版是否做同样强校验未核（其校验在 `InitControlConf`/`UpdateControlConf`，本轮未读）→ **待核**。
- 标定表建表用 `ACHECK`（lon_controller.cc 165–166 / lon_plus 189）：表为空或格式错会**直接 abort 进程**，不是返回错误。
