## 0. 一句话作用

本文是 **CyberRT 命令行工具链的实测手册**：`/opt/apollo/neo/bin` 里到底有哪些 `cyber_*` 与
`mainboard`、每个工具的参数以**源码为准**是什么、哪些参数是坏的、哪些「常见做法」在本机（11.0.0 包
工作区）根本走不通。定位：调试链路的入口层——判断某个 PnC 模块「起没起来 / 发没发消息 / 频率对不对」
全靠这一层，模块内部机制见 `../12_planning源码/02_planning_component主循环.md`。

## 3. 注册与配置（工具依赖的路径与环境）

- `mainboard` 解析 `module_library` 用 `GetFilePathWithEnv(..., "APOLLO_LIB_PATH")`，本机
  `APOLLO_LIB_PATH=/opt/apollo/neo/lib` → **只 `bazel build` 编出的 .so 工具看不见，必须
  `buildtool build -p <包路径>` 完成 install**（CLAUDE.md §2 同结论）。
- 插件索引 `/opt/apollo/neo/share/cyber_plugin_index/`（`APOLLO_PLUGIN_INDEX_PATH`），
  `APOLLO_PLUGIN_SEARCH_IN_BAZEL_OUTPUT=0` → 别去 `bazel-bin` 找索引。
- python 工具的**实际执行副本**在 `/opt/apollo/neo/bin/<tool>.runfiles/__main__/cyber/tools/...`
  （`cyber_launch` 裸跑 Traceback 自报此路径）；本轮 `diff` 实测
  `src/.../cyber_channel.py` 与 runfiles 副本**逐字节一致**，故源码结论对运行行为有效。
  改了 src 不 install 则运行副本不变。
- launch/dag 的绝对路径以 ④ 层 `/apollo/<src_path>/{launch,dag}/` 为准（内部是符号链接，
  落点可能是 `profiles/current` 覆盖层而非 share，见 `00_versions`）。

## 5. ⚠️ 本环境注意

**① `cyber_channel -w/--window` 彻底不可用（源码级证据）**
`cyber_channel.py:133`（`bw`）与 `:241`（`hz`）都写 `import string; window_size = string.atoi(...)`。
Python 3 的 `string` 模块**没有 atoi**，调用抛异常 → 被 `:136-137` / `:244-245` 的裸 `except`
捕获 → `parser.error("window size must be an integer")` 直接退出。所以**任何 `-w N`（哪怕 `-w 10`）
都必然失败**，且报错信息误导人以为「参数格式不对」。不加 `-w` 才正常（默认 `-1` 走默认窗口）。
runfiles 执行副本与 src 逐字节一致，bug 在真正运行的文件里。

**② `buildtool info <pkg>` 崩溃（本轮实跑复现）**
在 `/apollo_workspace` 跑 `buildtool info planning`：
`core/action/info.py:109` → `core/package_identification/identifier.py:113`
`root = ET.fromstring(cyberfile_contents)` → `TypeError: a bytes-like object is required, not 'list'`
（read 核过 identifier.py:110-121，该函数签名收的是「一堆 cyberfile 内容的 list」却直接喂给
`ET.fromstring`）。**替代**：直接读 `/opt/apollo/neo/share/packages/<pkg>/cyberfile.xml`。
另注：在非工作区目录（如 `/apollo/modules`）跑会先报 `Can not find WORKSPACE`，那是另一个错，别混。

**③ 裸跑退出码不统一（可作为「工具存在且可执行」的判据）**
`mainboard -h`=0、`cyber_monitor -h`=0、`cyber_recorder info -h`=0、`cyber_benchmark_{reader,writer} -h`=0、
`cyber_record_parser`（缺参）=0；`cyber_recorder`（缺参）=**255**；
`cyber_channel`/`cyber_node`/`cyber_service` 裸跑=**64**（`os.EX_USAGE`）；
`cyber_launch` 裸跑=**1 且是 Traceback**（`cyber_launch.py:563 command = sys.argv[1]` → IndexError，
argparse 的 subparsers 没设 required，先解析成功再越界取 argv[1]）。**别把 exit≠0 当成工具坏了。**

**④ `buildtool bootstrap start <x>` 的模块名限制：实测 15 个，不是 CLAUDE.md 说的 12 个**
`boot.py:31-61` `run_module` 拼的路径是 `/apollo/modules/<module_name>/launch/<name>.launch`
（:48-49），不存在就报 `ModuleIsNotInstallErr`（:50-54）；命中后其实只是
`cyber_launch start <launch> > <log_dir>/<module>.log 2>&1 &`（:57-60）。传 `.launch` 结尾的路径
也接受（:43-46），但 `check_module_is_running`（:63-68）按 `/apollo/modules/<name>/launch/<name>.launch`
做 pgrep，**手动起的进程它管不到**。
本轮遍历 `/apollo/modules`（37 个目录）满足「目录名 == launch 文件名」的是 **15 个**：
`canbus dreamview dreamview_plus loam_velodyne loam_velodyne_indoor localization
localization_intergrate monitor prediction routing safety_manager slam_local slam_local_indoor
statistics storytelling`。CLAUDE.md 的 12 个清单**已过期**（缺 `safety_manager`、`statistics`、
`slam_local_indoor`），以本次实测为准（2026-09-08）。**结论不变：绕开 bootstrap，launch 用
`cyber_launch start`，dag 用 `mainboard -d`。**

**⑤ `cyber_performance` 是无鉴权 Web 服务**（`:788` `host="0.0.0.0"`，默认 5000 端口）。
本轮**故意没有裸跑**它（会起服务器）。要用就临时起、用完 Ctrl-C，别在联网车上常驻。

**⑥ 其他**：`cyber_monitor` 对 `/perception/inner/*` 永远空（传 C++ 指针不序列化，不是故障）；
`aperf` 本环境没装成命令（源码在 `src/modules/tools/aperf`），替代品即 `cyber_performance`；
搜 `/apollo/...` 目录内容必须 `grep -R`（`-r` 不跟随符号链接会假空）。

## 6. 调试工作流（各问题用哪条命令）

来源：`apollo-dev/modules/debug/README.md`（本轮 read），命令形态已与本文
§2 的源码参数逐条对齐；下面的 channel 名与阈值出自该 skill，本轮**未起模块实测**。

| 问题 | 第一条命令 | 看什么 |
|---|---|---|
| 模块起没起来 / 秒退 | `mainboard -d <dag绝对路径>` | 前台日志；无任何输出 → dag 的 `module_library` 路径错 |
| 有哪些 channel / 消息类型 | `cyber_channel list`；`cyber_channel type <ch>` | 名字对不对，别猜 |
| 谁在发、谁在收 | `cyber_channel info <ch>`（或 `cyber_node list` / `info <node>`） | writer 与 reader 必须**同时**出现；只有 writer 查 `CYBER_DOMAIN_ID`/`CYBER_IP` |
| 频率不对 | `cyber_channel hz <ch>`（**不加 `-w`**） | 与 dag `interval`(ms) 或上游发布率比 |
| 消息内容对不对 | `cyber_channel echo <ch>` | 靠 proto_desc 动态解析，无需编译 |
| 带宽/大包 | `cyber_channel bw <ch>` | 找体积大户（点云类） |
| 一屏总览 | `cyber_monitor`（`-c <ch>` 单看） | 交互键：f 帧率 / t 类型 / →进入 / q 退出 |
| service 类命令没反应 | `cyber_service list` | `/apollo/external_command/*` 在不在 = processor 注册了没 |
| 性能/延迟 | `cyber_performance` + 浏览器 `:5000` | 各 component 的 proc/cyber latency（注意 §5-⑤） |
| 录一段现场 | `cyber_recorder record -a -k <大 channel> -o my.record`（或 `-c` 白名单） | `-i 秒` / `-m MB` 切段 |
| 回放联调 | `cyber_recorder play -f my.record -l -k <自己要产出的 channel>` | 再 `cyber_channel hz <自己输出>` 确认 |
| 包里有什么 | `cyber_recorder info my.record` | channel 列表、消息数、时间范围、is_complete |
| 起来后的固定巡检顺序 | 逐个 `cyber_channel hz` | `/apollo/localization/pose` → `/apollo/perception/obstacles` → `/apollo/prediction` → `/apollo/planning` → `/apollo/control`，第一个断处即问题所在（SKILL.md:111-113） |
