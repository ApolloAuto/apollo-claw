# 02 在本工作区动手前置核对清单

> 换机器/换环境后，先花两分钟核对再相信本手册任何结论。判定「我是哪版环境」→「关键运行前提」两步走。浓缩自工作区 CLAUDE.md §八 + §三（env 实测值），本工作区现场值即为表格中的「本机实测值」列。

## 第 1 步：判形态与版本（4 条，~1 分钟）

```bash
ls apollo.sh setup.sh .workspace.json 2>/dev/null   # 有 apollo.sh=整仓；有 setup.sh=package 工作区

ls /opt/apollo/neo/include/modules | wc -l          # 本机 39；差值 = 只发头文件的包数
ls /opt/apollo/neo/packages | wc -l                 # 本机 45
ls /opt/apollo/neo/share/cyber_plugin_index | wc -l # 本机 118（2026-09-08 实测；随安装变化，CLAUDE.md 写的 113 已过时）
```

## 第 2.5 步：检测 profile 覆盖层（每个环境必做，~1 分钟）

> **`profiles/current` = 当前环境的参数目录，是软链接、可改**：它指到的配置集就是现在生效的参数树；改 current 指向 = 切换当前配置集。④ 层多数 conf/dag 软链指向它，所以"改 conf 生效在哪"取决于落点。本机实测（2026-09-08）：`current → ARCF_40P`，`/apollo/modules` 下 374 条软链→profile、339 条→share。

```bash
# ① 有哪些配置集 + 当前激活哪套
ls /apollo_workspace/profiles/
readlink /apollo_workspace/profiles/current          # 例如 ARCF_40P（读原指向，改前备份）

# ② 切换当前配置集（current 是可改的软链接；改前先记录原指向）
# ln -sfn <新配置集名> /apollo_workspace/profiles/current

# ③ 抽查关键文件落点：落点 = current/... → profile 覆盖层；落点 = share/... → 出厂件
readlink /apollo/modules/planning/planning_component/dag/planning.dag
readlink /apollo/modules/planning/planning_component/conf/planning.conf
readlink /apollo/modules/control/control_component/dag/control.dag
readlink /apollo/modules/planning/planning_component/launch/planning.launch   # launch 一般在 share

# ④ 全量统计落点分布（判断覆盖层规模）
find /apollo/modules -type l -printf '%l\n' | grep -c 'profiles/current'   # →profile 条数
find /apollo/modules -type l -printf '%l\n' | grep -c '/opt/apollo/neo/share' # →share 条数
```

**判定与含义**：

| 落点 | 改它之后 | 会不会被 install 覆盖 |
|---|---|---|
| `/apollo_workspace/profiles/current/<sp>/...`（覆盖层） | **立即生效**，写穿到 current 配置树 | **不会**（profile 层是调参/运行配置的家） |
| `/opt/apollo/neo/share/<sp>/...`（出厂件） | 立即生效 | **会**（下次 `buildtool build/install` 被覆盖） |
| `/apollo_workspace/modules/<sp>/...`（工作区源码副本） | **不生效** | —（要 `buildtool build -p` 重编 install 才生效） |

⚠️ 三个推论（本机已实测）：
- **改 conf 不生效，先查落点**：落点在 share 且被 install 覆盖过、或落点在源码副本没重编，都表现为"改了没效果"。
- **profile 覆盖 pipeline 会制造孤儿 conf**：profile 版 pipeline 改了 task/stage 别名后，share 带来的旧实例 conf 永久失联（静默走 default），本机已抓 7 个（见 `00_版本基线对照.md` §5 #24）。
- **切 current 前必备份**：current 是软链接不是目录，`cp -r` 前先 `readlink` 记原指向；切错 = 整套生效配置换掉。
