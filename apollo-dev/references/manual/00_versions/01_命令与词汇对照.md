# 01 命令与词汇对照（11.0 ↔ PNC/EDU）

> 同一意图，两版各自命令。左侧 `[11.0·实测]`（CLAUDE.md/分册），右侧 `[EDU·上游]`（SKILL.md 高频快答与 knowledge/02_日常工作流）。
> **修订 2026-09-08**：本机同样存在 profiles 覆盖层（`profiles/current→ARCF_40P`），早前「11.0 无 profiles」的表述已按实测更正，详见 `00_版本基线对照.md` §5 #2/#17。
> 判断自己身在哪个环境：见 `02_在本工作区动手前置核对清单.md`。

| 意图 | 11.0（本工作区） | PNC/EDU | 备注 |
|---|---|---|---|
| 进入开发环境 | 已在容器内（本机即工作区）；无 aem 入口 | 宿主机 `cd application-pnc && aem start && aem enter` | EDU 版第一步 [EDU·上游] |
| 拉取模块源码 | `buildtool install planning`（-l 只装二进制） | `buildtool install planning*`（全量）或 `buildtool install planning-traffic-rules-crosswalk` | 同为 buildtool install；11.0 按包名不带 * 也行 |
| 编译 | `buildtool build -p modules/planning/planning_component`（-p 后是**路径**） | `buildtool build -p core` / `buildtool build -p modules/planning/` | EDU 版习惯 -p core 起步 [EDU·上游] |
| 编译后恢复配置 | **本机同样有 profiles 覆盖层**（`profiles/current→ARCF_40P`）：④ 层 conf/dag 多数软链指向它，改软链=写穿 profile 树、即时生效；本机无 `aem profile` 命令层，重编后是否需重挂软链**待核** | ⚠️ 必须 `aem profile use default`，否则 buildtool 覆盖 profiles 软链 | EDU 版每次编译后多一步；本机机制同源但无该命令 |
| 获取/初始化官方配置 | 调参直接改 `/apollo/<sp>/conf/*`（先 `readlink -f` 判落点：profile 覆盖层或 share 出厂件；planning 子树实测 127 profile / 285 share） | `buildtool profile config init --package planning --profile=default`，或 `mkdir -p profiles/default/modules && cp -r .aem/envroot/opt/apollo/neo/share/modules/planning profiles/default/modules/` 后 `aem profile use default` | profiles **机制两版同源**，EDU 版多了 buildtool/aem 命令层 |
| 切换配置集 | 目录级有多套（`profiles/{ARCF_40P, ARCF_40P_NDT, sample}` + `current` 软链），切换=改 `current` 指向；本机无 `aem profile use` 实测记录（待核） | `aem profile use <名字>`（如 tmp 临时 profile 释放软链） | — |
| 启动全部仿真 UI | `buildtool bootstrap start dreamview_plus`（可用名单仅 12 个模块名，见 CLAUDE.md §二） | `aem bootstrap start --plus` | EDU 版入口带 --plus [EDU·上游] |
| 单模块启动（planning） | `mainboard -d /apollo/modules/planning/planning_component/dag/planning.dag` | 同左（SKILL 速查卡片原文一致） | [通用] |
| 启动/停止 launch | `cyber_launch start/stop <launch 绝对路径>` | 未在知识库出现 launch 用法 | 11.0 推荐形态 |
| 查看/调试 | cyber_channel/cyber_monitor/cyber_recorder 等（注意 -w 坏） | 知识库用 DreamView 面板与日志为主 | — |
| 清理日志 | `find data/log/ -name "*.log.*20[0-9][0-9]*" -type f -delete`（在 /apollo/data/log 下） | `find data/log/ -name "*.log.*20[0-9][0-9]*" -type f -delete`（SKILL 高频答原文） | 命令同 [通用]，所在目录同 data/log |
| 打包提交 | 无固定仪式；代码改动提交 `/apollo_workspace/<sp>` | 只改配置：`tar -zcvf 提交包.tar.gz profiles/default`；改了源码：`tar -zcvf 提交包.tar.gz modules/planning/ profiles/default` | EDU 版仪式 [EDU·上游] |
| Git 保存/回退 | `git add/commit` 于工作区（`profiles/` 也在工作区内，可一并纳管） | 宿主机 git；`git checkout -b scene/crosswalk` 场景分支；切分支后重跑 `aem profile use default` | EDU 版含配置进 git [EDU·上游] |
| 模块坏了恢复 | 备份→buildtool reinstall planning*→buildtool install→build→恢复 conf | 同左（SKILL「Planning 模块恢复」卡片） | 流程同构 [通用] |
| 查看版本基线 | `cat .workspace.json`、`ls apollo.sh setup.sh` | 未在知识库出现 | 判别环境第一命令 |

## 词汇对照（同概念不同叫法）

| 概念 | 11.0 叫法/位置 | EDU 版叫法/位置 |
|---|---|---|
| 配置文件树 | `/apollo/<sp>/conf/`（软链）→ **`/apollo_workspace/profiles/current/<sp>/`（覆盖层，多数 conf/dag）或 `/opt/apollo/neo/share/<sp>/`（出厂件，launch 全在此）** | `profiles/default/`（软链）→ `.aem/envroot/opt/apollo/neo/share/...` |
| 源码副本 | `/apollo_workspace/<sp>/` | 容器内 `modules/planning/`（相对 application-pnc 工程） |
| 安装树 | `/opt/apollo/neo/{lib,include,share,src}` | `.aem/envroot/opt/apollo/neo/...` |
| 选图/地图目录 | dreamview 写 `global_flagfile.txt` 末行 map_dir | EDU 场景集加载（buildtool map get） |
