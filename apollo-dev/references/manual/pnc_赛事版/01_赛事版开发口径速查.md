## 1. 版本与形态声明

- **EDU 版形态**：application-pnc 工程 = aem 容器环境 + buildtool 包管理 + `profiles/` 软链配置机制 + `modules/` 源码目录（用 `buildtool install` 拉取、可修改）；容器内工作目录 `/apollo_workspace`，配置生效目录 `/apollo`（`.aem/envroot/apollo` 挂载，`.aem/envroot/opt` 挂载 `/opt` 缓存已装包）。
- **机制源流**：包管理 2.0 / 插件扩展（scenario、task、traffic rule）/ 分级参数配置（全局+局部）/ profile 是 Apollo 9.0 起引入并沿用至EDU 版的口径；本套 knowledge 即按此口径编写（个别老文为 8.0 时代插件下载机制）。
- **与 11.0 的关系一句话**：同一套"包管理 2.0 + 插件 + profile"框架在 11.0 package 工作区延续存在，但本机 11.0 无 `application-pnc`/`peixun`，命令与路径细节可能不同——凡动手前先对照 `../00_versions/`（版本基线对照 / 命令词汇对照 / 动手前置核对清单），冲突以 11.0 源码层手册为准。
- 目录三层示意（`01_PnC开发模式说明.md`）：`application-core/.aem/envroot/{apollo,opt}`、`modules`（可改源码）、`profiles/{current -> default, default, …}`。

来源：`03_规划PnC/01_PnC开发模式说明.md`、`05_工程框架与工具/工程框架升级之包管理2.0整体解读.md`、`references/manual/00_readme.md`

## 2. 每日开发流程（进入环境 → 拉代码 → 编译 → 恢复配置 → 起仿真）

```bash
# 宿主机
cd application-pnc
aem start          # 启动容器（已启动可跳过；08 篇只写 aem enter，若进不去先 aem start）
aem enter          # 进入容器（用户名变 in-dev-docker）

# 容器内（/apollo_workspace）
buildtool build -p core            # 有代码改动时先编 core（电脑重启后工作流 3）
buildtool build -p modules/planning/   # 或只编 planning（工作流 2）
aem profile use default            # ⚠️ 编译后必做：恢复 profile 软链，否则配置被覆盖
aem bootstrap start --plus         # 启动 Dreamview（端口 http://localhost:8888/，ctrl+点击或浏览器打开）
```

- 改参数调优（工作流 1）：编辑 `profiles/default` 下配置 → 起仿真 → Dreamview 选场景跑 → 观察调整 → 打包。
- 改源码（工作流 2）：`buildtool install planning*` 拉码 → 改 `modules/planning/` → 编译 → `aem profile use default` → 起仿真 → 打包。
- Dreamview 已运行提示 `Moduledreamview is already running - skipping.` 时：`aem bootstrap stop` 后重起，或 `aem bootstrap restart`。

来源：`SKILL.md`（工作流 1~3）、`02_日常工作流/08_电脑重启后怎么进入Apollo.md`、`03_规划PnC/04_使用SimControl仿真调试.md`

## 4. profile 机制详解

**原理**：`profiles/current` 是指向启用配置目录的软链；使用 profile 后 `/apollo` 下的配置文件软链指向 `profiles/` 下对应文件（`/apollo/xxx` 绝对路径逻辑优先读 profile）。**默认情况下 profile 目录是空的**——不存放任何配置时，软链优先使用编译产出配置；同步后 profile 中才会出现与默认配置相同的文件。

**目录结构**：

```
profiles/
├── current -> default    # 软链，当前启用（ll profiles/current 查看）
├── default               # 测评系统只读 default 目录下的配置参数 ⚠️
├── demo_1 / demo_2       # 可多份，按场景/按人切换
└── demo_1/modules/planning/planning_base/conf/…   # 只需保留要改的文件，其余读模块默认配置
```

**常用命令**：

```bash
aem profile list              # 查看已有 profile
aem profile use default|demo_1|tmp    # 切换（改变 current 软链指向）
buildtool profile config init --package <包名> --profile=<目录名>   # 同步某包配置到某 profile
ll profiles/current           # 查 current 指向
ll /apollo/modules/planning/planning_component/conf/   # 排查：查容器内配置是否指向 current
```

**编译后配置丢失/被覆盖的根因与恢复**：`buildtool build` 会覆盖 `profiles/` 下的软链配置；本地下载源码也可能导致配置不生效。**编译后（或切分支后）务必重新执行 `aem profile use default`**。排查三步：① `ll profiles/current` 看软链 ② `ll /apollo/modules/planning/planning_component/conf/` 看指向 ③ 不对就重跑 `aem profile use default`。

**打包提交**（`02_日常工作流/09_赛事压缩包制作.md`）：

```bash
tar -zcvf 提交包.tar.gz profiles/default                    # 只改了配置
tar -zcvf 提交包.tar.gz modules/planning/ profiles/default  # 改了源码+配置
```

**planning 打不开/代码损坏恢复序列**（容器内，SKILL.md 速查卡片）：先 `tar` 备份 `modules/planning/` 与 `profiles/default/` → `mkdir -p profiles/tmp && aem profile use tmp`（释放 default 软链）→ `rm -rf profiles/default modules/planning` → `buildtool reinstall planning*` →（可选）`buildtool install planning*` / `buildtool build -p modules/planning/` → `buildtool profile config init --package planning --profile=default && aem profile use default`。

来源：`02_日常工作流/06_aem_profile配置管理.md`、`03_规划PnC/03_Planning2.0参数配置.md`、`03_规划PnC/00_代码与配置下载指南.md`、`02_日常工作流/09_赛事压缩包制作.md`、`SKILL.md`

## 5. 插件开发口径

### 5.1 TrafficRule 插件（案例：交汇路口限速 RegionSpeedLimit）

完整流程源：`03_规划PnC/05_新增TrafficRule插件流程.md`（快上手）、`03_规划PnC/06_插件机制—新增TrafficRule插件.md`（完整版）、`08_实践—交汇路口减速慢行插件.md`（指路）。

1. **生成模板**（在 `modules/planning/traffic_rules/` 下建插件目录）：
   ```bash
   buildtool create --template plugin --namespaces planning --name region-speed-limit \
     --base_class_name TrafficRule modules/planning/traffic_rules/region_speed_limit \
     --config_message_name RegionSpeedLimitConfig
   ```
   > 另一变体（05 工程框架解读，参数更全）：追加 `--includes "…status.h" "…traffic_rule.h" "…pb.h"`、`--dependencies planning:planning`、`--build_dependencies "…"`、`--base_class_name apollo::planning::TrafficRule`。（来源：`05_工程框架与工具/工程框架升级之包管理2.0整体解读.md`）
   模板目录：`region_speed_limit/{region_speed_limit.cc, .h, conf/default_conf.pb.txt, proto/region_speed_limit.proto, proto/BUILD, BUILD, plugin_…_description.xml, cyberfile.xml}`（来源：06 篇 §2）。
2. **写代码**（改动点）：
   - `.cc`：`Init()` 先 `TrafficRule::Init(name, injector)` 再 `TrafficRule::LoadConfig<RegionSpeedLimitConfig>(&config_)` 读配置；`ApplyRule()` 取 `reference_line_info->reference_line().map_path().pnc_junction_overlaps()`，对每个 overlap 调 `reference_line->AddSpeedLimit(start_s - config_.forward_buffer(), end_s + config_.backward_buffer(), config_.limit_speed())` 实现区域限速。
   - `.h`：`class RegionSpeedLimit : public TrafficRule`，声明 `Init/ApplyRule/Reset()`，成员 `RegionSpeedLimitConfig config_`；末尾注册宏 `CYBER_PLUGIN_MANAGER_REGISTER_PLUGIN(apollo::planning::RegionSpeedLimit, TrafficRule)`（第二参 = 基类）。Reset() 是插件变量重置入口。
   - `proto/region_speed_limit.proto`：`message RegionSpeedLimitConfig { optional double forward_buffer = 1 [default=3]; optional double backward_buffer = 2 [default=2]; optional double limit_speed = 3 [default=5]; }`。
   - `conf/default_conf.pb.txt`（模板生成的文件名 region_speed_limit.pb.txt 改成这个）：`forward_buffer: 3.0 / backward_buffer: 2.0 / limit_speed: 15.0`。
3. **BUILD**：关键规则 `apollo_plugin(name = "libregion_speed_limit.so", srcs=[…], hdrs=[…], description = ":plugins.xml", deps=[…])`（deps 加 `//cyber`、`…/planning_interface_base:apollo_planning_planning_interface_base`、`…/proto:region_speed_limit_proto`）；`filegroup(name="…_files", srcs=glob(["conf/**"]))` 负责安装 conf；尾部 `apollo_package()` + `cpplint()`。
4. **插件描述文件**：把模板生成的 `plugin_region_speed_limit_description.xml` 改名 **plugins.xml**，内容：
   ```xml
   <library path="modules/planning/traffic_rules/region_speed_limit/libregion_speed_limit.so">
     <class type="apollo::planning::RegionSpeedLimit" base_class="apollo::planning::TrafficRule"></class>
   </library>
   ```
5. **cyberfile.xml**：声明包名/版本/依赖（模板已生成，按需填）。
6. **启用**：在 `traffic_rule_config.pb.txt` 的 rule 列表追加（name 为别名大写自定、type 为类名省略 namespace）：
   ```protobuf
   rule { name: "REGION_SPEED_SETTING" type: "RegionSpeedLimit" }
   ```
7. **编译与验证**：
   ```bash
   buildtool build -p modules/planning/traffic_rules/region_speed_limit/
   aem bootstrap start --plus
   ```
   调 `default_conf.pb.txt` 里 `limit_speed: 3` → Dreamview 观察路口限速（原文：路口前 ~23km/h → 路口 ~10km/h）。
8. **配置进 profile**：自定义插件不能用 `buildtool profile config init` 同步，需手动把 conf 复制到 profile（方式 B）或直接在 profile 对应插件 conf 下编辑。

来源：`03_规划PnC/05_新增TrafficRule插件流程.md`、`03_规划PnC/06_插件机制—新增TrafficRule插件.md`、`03_规划PnC/08_实践—交汇路口减速慢行插件.md`

### 5.2 Scenario 插件（案例：左转待转 TrafficLightLeftTurnWaitingZone）

完整流程源：`03_规划PnC/07_插件机制—新增Scenario插件.md`（→ 集锦 `04_赛事集锦/01_场景—左转待转.md`）。

1. **生成模板**（`modules/planning/scenarios/` 下）：
   ```bash
   buildtool create --template plugin --namespaces planning \
     --dependencies planning:binary:planning \
     --base_class_name apollo::planning::Scenario \
     --class_name TrafficLightLeftTurnWaitingZone \
     modules/planning/scenarios/traffic_light_left_turn_waiting_zone
   ```
2. **场景类**（scenarios/traffic_light_left_turn_waiting_zone/…，文件名小写化）：实现 `Init()`（`Scenario::Init` + `Scenario::LoadConfig<…Config>(&context_.scenario_config)`）、`IsTransferable()`（切入条件：参考线首遇 overlap 为 SIGNAL 且在 `start_traffic_light_scenario_distance` 内、`GetPathTurnType` 为 LEFT_TURN、同组 2m 内有 `ARROW_LEFT` subsignal 且 `stop_line_size()>1` 的信号灯——靠地图元素判场景）、`Enter()`（把直行/左转信号灯 id 存入 context_）、`Exit()`（清 id、清 `done_traffic_light_overlap_id`）。头文件里 `struct …Context : public ScenarioContext` 装 config 与 id；注册宏 `CYBER_PLUGIN_MANAGER_REGISTER_PLUGIN(apollo::planning::TrafficLightLeftTurnWaitingZone, apollo::planning::Scenario)`。
3. **Stage**（每个 .h/.cc 一对，均注册宏第二参 `Stage`）：APPROACH（直行区等灯）→ CREEP（进待转区等灯）→ CRUISE（过路口）；每个 `Process()` 里 `reference_line_info.LimitCruiseSpeed(scenario_config.xxx_speed())` 设阶段限速，`ExecuteTaskOnReferenceLine(...)` 执行任务，切阶段返回 `FinishStage("…")` / `FinishStage()`（CRUISE 可继承现成基类 `BaseStageTrafficLightCruise`，用 `CheckDone()` 判完成）。
4. **conf/pipeline.pb.txt**：按 `stage { name/type/enabled: true/task{name type}… }` 编排三阶段与每阶段 task（复用库内 LANE_FOLLOW_PATH、PATH_DECIDER、RULE_BASED_STOP_DECIDER、SPEED_BOUNDS_PRIORI_DECIDER、SPEED_HEURISTIC_OPTIMIZER、SPEED_DECIDER、SPEED_BOUNDS_FINAL_DECIDER、PIECEWISE_JERK_SPEED 等）。
5. **参数**：proto 定义 `TrafficLightLeftTurnWaitingZoneConfig{start_traffic_light_scenario_distance, approach_speed, creep_speed, cruise_speed}`；`conf/scenario_conf.pb.txt` 写值（示例 30.0/5.0/3.0/8.0）；proto/BUILD 用 `proto_library(name="…_proto", srcs=[…])`。
6. **插件描述文件**：`plugin_traffic_light_left_turn_waiting_zone_description.xml` 内 1 个 `<library path="…/libtraffic_light_left_turn_waiting_zone.so">` 下挂 4 个 `<class>`（Scenario 一个 + 3 个 Stage，`base_class` 分别 `apollo::planning::Scenario`/`apollo::planning::Stage`）；BUILD 的 `description=":plugin_…_description.xml"`。
7. **启用**：在 planning 场景管理流水线 `profiles/current/modules/planning/planning_component/conf/planning_config.pb.txt` 的 `standard_planning_config.planner_public_road_config` 下追加：
   ```protobuf
   scenario { name: "TRAFFIC_LIGHT_LEFT_TURN_WAITING_ZONE" type: "TrafficLightLeftTurnWaitingZone" }
   ```
   （其余 scenario 保持不动；场景列表书写顺序即优先级语义。）
8. **编译验证**：
   ```bash
   buildtool build -p modules/planning/scenarios/traffic_light_left_turn_waiting_zone
   sudo apt install apollo-neo-tools    # 需要 tools 时
   python3 modules/planning/scenarios/traffic_light_left_turn_waiting_zone/tools/manual_traffic_light.py
   ```
   Dreamview 选场景→放车到左转车道→起 planning→脚本键盘 1/2/3/4 切"全红/直行绿/左转绿/全绿"→Routing 发请求→按灯色观察三阶段切换。

来源：`03_规划PnC/07_插件机制—新增Scenario插件.md`

## 6. 参数配置口径（全局/局部 + profile 目录）

- **划分**：全局参数 = planning_base（planning 基本流程/基础算法共用）；局部参数 = 各插件自带的 conf（scenarios / tasks / traffic_rules 三类目录），调某插件参数直接进插件目录找。proto 定义数据结构（`.proto`），conf 文件放实际值（`*.pb.txt`；gflags 用 `planning.conf`/`*.conf`）。（来源：`03_规划PnC/03_Planning2.0参数配置.md`）
- **全局参数目录**（planning_base）：`conf/planning.conf`（全局 flag）、`planning_config.pb.txt`（全局配置）、`traffic_rule_config.pb.txt`（traffic rule 生效列表，**列表顺序即执行顺序**）、`planner_open_space_config.pb.txt` 等；`common/planning_gflags.h`（flag 定义）；`scenario_base/proto/scenario_pipeline.proto`（pipeline 定义）。配置文件正文在 `modules/planning/planning_component/conf/`（navi 模式为 `planning_navi.conf`）。
- **profile 侧结构**（同步后与源码同构，好找）：`profiles/default/modules/planning/planning_base/` 平铺 conf/、planning.conf、planning_config.pb.txt、traffic_rule_config.pb.txt、dag/、launch/、testdata/；局部示例 `profiles/default/modules/planning/traffic_rules/<rule>/conf/default_conf.pb.txt`。
- **读取优先级**：组件配置 `profile > 默认`（后续会改"工作空间源码 > profile > 默认"）；插件配置 `工作空间源码 > profile > 默认`。profile 与源码目录保持同层级结构。
- **traffic rule 生效配置写法**（`traffic_rule_config.pb.txt`）：每条 `rule { name: "别名" type: "类名" }`（别名大写可自定义；type 为类名，省略 namespace）。规则自身参数在其插件 `conf/default_conf.pb.txt`，示例（crosswalk）：`stop_distance: 1.0 / max_stop_deceleration: 4.0 / min_pass_s_distance: 1.0 / expand_s_distance: 2.0 / stop_strict_l_distance: 4.0 / stop_loose_l_distance: 5.0 / start_watch_timer_distance: 10 / stop_timeout: 10.0`。
- **常用全局参数调参示例**（仿真验证法：改 → 重启 planning/编译 → Dreamview 观察）：`--default_cruise_speed=10.0`（巡航限速）、`--speed_bump_speed_limit=4.0`（减速带限速）、`--obstacle_lat_buffer=1.0`（绕行横向距离）；交通灯停车 `stop_distance: 2.0`（红灯停在停止线 2~2.5m 的调参实例）。全局参数同步命令：`buildtool profile config init --package planning --profile=default && aem profile use default`。

来源：`03_规划PnC/02_PnC包管理2.0解读.md`、`03_规划PnC/03_Planning2.0参数配置.md`、`05_工程框架与工具/工程框架升级之包管理2.0整体解读.md`

## 7. SimControl 仿真调试流程

（源：`03_规划PnC/04_使用SimControl仿真调试.md`；老文写 `cd pnc-competition`/`aem bootstrap`，EDU 新版见第 2 节命令）

1. 启动 Dreamview（容器内 `aem bootstrap start --plus`；老版 `aem bootstrap`），浏览器开 `http://localhost:8888/`；提示已运行时先 `aem bootstrap stop` 再启动。
2. 顶部选择：车辆型号 **MkzExample** → 地图 **Apollo Virtual Map**（EDU 场景图：下载场景集后选择）→ Tasks → **SimControl** 进入仿真模式。
3. 左侧 Module Control 启动要调试的模块：Planning、Prediction、Routing（SimControl 会模拟 Chassis/Localization/PerceptionObstacle 输入）。
4. 用 **Cyber_monitor** 或 **Module Delay** 确认模块有数据输出。
5. 左侧 **RoutingEditing** 在地图上点设起点-终点（或途径点），点 **Send Routing Request**；红线 = routing 搜索出的路径，浅蓝色轨迹 = planning 实时规划的局部路径。
6. 开 Tasks 里的 **PnC Monitor** 看 planning/control 数据曲线辅助调参。
7. 编译：planning `buildtool build -p modules/planning/`；其他模块 `buildtool build -p modules/模块名`。

来源：`03_规划PnC/04_使用SimControl仿真调试.md`、`05_工程框架与工具/Dreamview功能介绍.md`（界面元素：Tasks/Module Controller/Layer Menu/Route Editing/Default Routing 等，调试用 PnC Monitor、Module Delay、Console）

## 9. Git 与回退速查

（源：`02_日常工作流/10_Git代码与配置管理.md`；**宿主机** application-pnc 根目录执行，非容器内）

```bash
git init                                    # 首次；git config user.name/email 设一次
# .gitignore 必须排除：.cache/ bazel-* *.pyc __pycache__/ data/log/ data/record/ *.log .aem/ *.tar.gz *.zip .idea/ .vscode/
git add profiles/default/                   # 配置：必须管理（测评只读 default）
git add modules/planning/                   # 源码：下载过才管理
git commit -m "[场景名] 改了什么 → 效果"       # 例：[人行道] stop_distance 8.0→6.0
```

**分支管理**：`main` 存综合最优；每场景一支 `scene/crosswalk`、`scene/lane-borrow`、`scene/intersection`、`scene/parking`、`experiment/xxx`。切分支后**必须** `aem enter && aem profile use default` 再 `exit`，否则 Apollo 仍读旧配置。

**远端**：GitHub/Gitee 建私有仓库 → `git remote add origin <url>` → `git push -u origin main`、`git push origin scene/xxx`；新机器 `git clone` → `git fetch --all` → `git checkout <branch>` → 重装容器后 `aem start && aem enter && aem profile use default`；需重编则 `buildtool build -p modules/planning/ && aem profile use default`。

**常用速查**：

```bash
git status / git diff profiles/default/                 # 查改动
git log --oneline --graph --all / git show <hash>       # 看历史/某次提交
git checkout HEAD -- profiles/default/                  # 回退配置到 HEAD（代码：modules/planning/）
git checkout <commit-hash> -- profiles/default/         # 回退到某个历史提交（查看效果，不改历史）
git reset HEAD~1                                        # 撤销最近一次提交（保留文件改动）
git reset --hard <hash>                                 # ⚠️ 强退到某版本（丢失此后提交）
git stash / git stash pop                               # 临时切分支前暂存/恢复
git merge scene/xxx                                     # 分支成果合入主干
git diff main scene/xxx -- profiles/default/            # 对比分支配置差异
```

来源：`02_日常工作流/10_Git代码与配置管理.md`、`SKILL.md`（高频快答）
