## 0. 一句话作用

perception 是 PnC 的**上游数据源**：31 个子包拆成 lidar / camera / traffic_light / radar 四条流水线，各级用 `/perception/inner/*`、`/perception/lidar/*` 逐级串联，最后由 `multi_sensor_fusion` 汇成 **`/apollo/perception/obstacles`**，TL 链单独汇成 **`/apollo/perception/traffic_light`**——PnC 只认这两条，其余一律是感知内部通道。本文只讲骨架与链路走向，不讲算法。

## 2. 四大链路与 channel 流

dag **只声明输入**（`readers{channel}`）；输出 channel 一律在 conf 的 `output_*_channel_name`（本轮 `grep -R` 全量提取，见 §2.5）。

### 2.1 链路图

```
/apollo/sensor/velodyne64/compensator/PointCloud2
   → pointcloud_preprocess → /perception/lidar/pointcloud_preprocess
   → pointcloud_map_based_roi → /perception/lidar/pointcloud_map_based_roi
        ├→ pointcloud_semantic → pointcloud_motion（旁路语义/运动）
        └→ pointcloud_ground_detection → /perception/lidar/pointcloud_ground_detection
   → lidar_detection | lidar_cpdet_detection → /perception/lidar/detection
        ├→ lidar_segmentation → /perception/lidar/segmentation
        └→ lidar_detection_filter → /perception/lidar/detection_filter
   → lidar_tracking ─────────────────────────────┐
                                                 │
/apollo/sensor/camera/camera_front/image         │
   → camera_detection_multi_stage → /perception/inner/Detection(2)
   → camera_location_estimation  → /perception/inner/location_estimation(2)
   → camera_location_refinement  → /perception/inner/location_refinement(2)
   → camera_tracking ────────────────────────────┤→ /perception/inner/PrefusedObjects
                                                 │      → multi_sensor_fusion
/apollo/sensor/radar/front|rear                  │           ↓
   → radar_detection ────────────────────────────┘   /apollo/perception/obstacles ⇒ prediction

/apollo/sensor/camera/front_12mm/image（conf 选相机，非 dag）
   → traffic_light_region_proposal → /perception/inner/Detection
   → traffic_light_detection       → /perception/inner/Retection   ← 源码原样拼写
   → traffic_light_recognition     → /perception/inner/Tracking
   → traffic_light_tracking        → /apollo/perception/traffic_light ⇒ planning
```

## 3. 与 PnC 的接口边界

| channel | 消息类型 | perception 侧发布者 | PnC 侧消费者 | 说明 |
|---|---|---|---|---|
| /apollo/perception/obstacles | `apollo::perception::PerceptionObstacles` | multi_sensor_fusion（正常）/ lidar_output / msg_adapter（离线） | **prediction（dag 唯一 reader，depth 1）** | prediction 停 ⇒ planning 断节拍（见 `../14_数据与消息/01_PnC链路channel全景.md`） |
| /apollo/perception/traffic_light | `apollo::perception::TrafficLightDetection` | traffic_light_tracking | planning（traffic_rule / scenario） | TL 链断则红绿灯规则拿不到观测 |

**边界铁律**：`/perception/inner/*` 与 `/perception/lidar/*` 全部是感知内部级联通道，**PnC 一律不订、也不要新增订阅**；其中 `/perception/inner/Retection` 是**源码原样拼写**（TL detection→recognition 之间），写成 `Detection` 会静默收不到消息（本轮已在 `traffic_light_recognition.dag:11` 与 traffic_light_detection conf 两侧确认拼写一致）。

## 5. ⚠️ 本环境注意（11.0 包工作区实测）

1. **模型权重 12/17 有、5 空**（本轮逐目录实测「除 BUILD/README 外文件数」）：空的是 `cnnseg16_caffe` / `cnnseg64_caffe` / `cnnseg128_caffe` / `point_pillars_torch` / `mask_pillars_torch` → **cnnseg 系分割与 point_pillars / mask_pillars 检测跑不了**（起得来、不出障碍物）。有权重的 12 个里 7 个来自 `profiles/current`（人工放入，非 apt install 产物）。CLAUDE.md 第五节「16 目录 / 只有 5 个有权重」**已过期**（本轮 2026-08-11 后实测 17/12/5）。
2. **launch 数三口径都不同**：src 树 21、share 层 20（缺 `lidar_output/launch/lidar_output.launch`，install 未发布）、`/apollo` 运行时 `find -L` 28（= 子包 20 + profile 聚合 8）。CLAUDE.md 的「73 个」无任何现口径吻合（全仓 src 71 / 全仓运行时 86）。
3. **`camera_detection_bev/dag/camera_detection_bev.dag` 只在 src 树**：`/opt/apollo/neo/share/modules/perception/camera_detection_bev/dag/` 本轮 `ls` 报 **No such file or directory** → 运行时视口无此 dag，直接 `mainboard -d /apollo/...bev.dag` 会找不到文件。src dag 39 / share dag 38，差的就是它。
4. **`outside_roi_filter` 装了描述没装库**：`lidar_detection_filter/object_filter_bank/outside_roi_filter` 在 src/share 有 plugins.xml，`/opt/apollo/neo/lib/.../outside_roi_filter/` 目录存在但**空**（本轮 `ls -R` 实测），`cyber_plugin_index` 匹配条目数 = 0 → 任何 conf 引用它都会加载失败（哪个 conf 引用，待核）。
5. **conf 落点必须 `readlink -f` 判层**：本轮实测 `multi_sensor_fusion` 与 `traffic_light_region_proposal` 的 conf 落在 **profile 覆盖层** `/apollo_workspace/profiles/ARCF_40P/...`，而 `traffic_light_tracking` 的 conf 落在**出厂层** `/opt/apollo/neo/share/...`。同一模块两种落点混存，别假设一律指向 share。
6. **搜 `/apollo/...` 用 `grep -R` 不是 `-r`**：运行时层全是符号链接，`-r` 不跟随会返回空，容易误判「这个 channel 没人引用」。
7. 插件索引在 `/opt/apollo/neo/share/cyber_plugin_index/`（本环境 `APOLLO_PLUGIN_SEARCH_IN_BAZEL_OUTPUT=0`，**不扫 bazel-bin**）；perception 相关注册 14 条**全属 lidar 家族**，camera / radar / TL / fusion / lane 分支**无插件注册**（静态链接在组件内）。[盘点] §3
8. `perception_all.launch` 里 **`lidar_detection` 被注释、跑的是 `lidar_cpdet_detection`**（两者 dag 同名、读同一输入 channel），排查「检测没输出」先确认在跑哪一个。
9. 本环境**没有** `modules/perception/production/`；聚合入口靠上面 8 个 profile launch，换 profile（`aem profile use <x>`）会整批换掉。
