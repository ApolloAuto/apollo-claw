## 0. 一句话作用

lidar 链最上游的 5 个子包，把原始点云 `/apollo/sensor/velodyne64/compensator/PointCloud2` 逐级
「裁剪去噪 → 按地图裁 ROI → 地面点分离 / 语义分割（旁路）→ 运动特征」之后，交给 `lidar_detection`。
5 个包同构：每个 = 1 个 `cyber::Component<T>` 外壳 + `interface/base_*.h` 抽象基类 + `conf` 里
`plugin_param` 三段式选实现。**组件都是 dag 拉起的（Component），但算法实现的取实例通道分两派**：
preprocess / ground / semantics / motion 走 **Registerer（同 .so 静态注册）**，map_based_roi 走
**PluginManager（动态 .so，本族唯一）**。骨架机制见
[`02_组件插件架构与子包骨架.md`](02_组件插件架构与子包骨架.md)，链路全景见
[`01_总览与四大链路.md`](01_总览与四大链路.md)。

## 1. 五个子包总表（必做①）

组件名 = dag `class_name`（= `CYBER_REGISTER_COMPONENT` 的非限定名）。dag 只声明输入（`readers`），
输出一律在 conf 的 `output_channel_name`。目录列只给关键子目录，完整清单见 §7 溯源。

| 包（`/opt/apollo/neo/src/modules/perception/<pkg>/`） | 组件名 | 输入 channel（dag readers）| 输出 channel（conf output_channel_name）| 一句话职责 | 关键 conf | 插件注册 |
|---|---|---|---|---|---|---|
| `pointcloud_preprocess` | `PointCloudPreprocessComponent` | `/apollo/sensor/velodyne64/compensator/PointCloud2` | `/perception/lidar/pointcloud_preprocess` | lidar 链入口：滤 nan/inf、车体近区、过高点；查 TF 位姿装进 LidarFrame | `conf/pointcloud_preprocess_config.pb.txt` + `data/pointcloud_preprocessor.pb.txt` | **Registerer**（`BasePointCloudPreprocessor`） |
| `pointcloud_map_based_roi` | `PointCloudMapROIComponent` | `/perception/lidar/pointcloud_preprocess` | `/perception/lidar/pointcloud_map_based_roi` | 按高精地图多边形裁 ROI，剔除路外点 | `conf/pointcloud_map_based_roi_config.pb.txt` + `data/{hdmap_roi_filter,map_manager}.pb.txt` | **PluginManager**（`BaseROIFilter`，2 个插件） |
| `pointcloud_ground_detection` | `PointCloudGroundDetectComponent` | `/perception/lidar/pointcloud_map_based_roi` | `/perception/lidar/pointcloud_ground_detection` | 地面点检测（填 `non_ground_indices` / `point_height`） | `conf/pointcloud_ground_detection_config.pb.txt` + `data/spatio_temporal_ground_detector.pb.txt`（生效）/ `ground_service_detector.pb.txt` | **Registerer**（`BaseGroundDetector`） |
| `pointcloud_semantics` | `PointCloudSemanticComponent` | `/perception/lidar/pointcloud_map_based_roi` | `/perception/lidar/pointcloud_semantic` | 点云语义分割（PointWiseUnet，GPU 推理） | `conf/pointcloud_semantic.pb.txt` + `data/pointwise_unet_param.pb.txt` | **Registerer**（`BasePointCloudParser`） |
| `pointcloud_motion` | `PointCloudMotionComponent` | `/perception/lidar/pointcloud_semantic` | `/perception/lidar/pointcloud_motion` | 点云运动特征（MotionUnet，两帧时序，GPU 推理） | `conf/pointcloud_motion.pb.txt` + `data/pointwise_motion_unet_param.pb.txt` | **Registerer**（`BaseMotionParser`） |

**关键差异一图**：

```
/apollo/sensor/velodyne64/compensator/PointCloud2          ← 唯一「原始点云」入口（drivers::PointCloud）
  → pointcloud_preprocess → /perception/lidar/pointcloud_preprocess        （Component<drivers::PointCloud>）
  → pointcloud_map_based_roi → /perception/lidar/pointcloud_map_based_roi  （Component<LidarFrameMessage>，PluginManager）
       ├→ pointcloud_semantics → /perception/lidar/pointcloud_semantic     （与 ground 并行）
       │     └→ pointcloud_motion → /perception/lidar/pointcloud_motion    （只吃 semantic）
       └→ pointcloud_ground_detection → /perception/lidar/pointcloud_ground_detection
```

- **preprocess 特殊**：是 5 包里唯一 `Component<drivers::PointCloud>`（吃原始传感器消息），其余 4 个都是
  `Component<onboard::LidarFrameMessage>`（吃上一级装配好的 LidarFrame）。见
  `pointcloud_preprocess_component.h:36-37`。
- **semantics 与 ground_detection 并行**，都直接读 map_based_roi 的输出；**motion 串在 semantics 之后**，
  不在主检测链上（`perception_lidar.launch` 就不含 motion，见 10 篇 §4）。
- 每个包的实例级 conf 名有坑：`pointcloud_semantics` 的 conf 叫 `pointcloud_semantic.pb.txt`、
  dag 叫 `pointcloud_semantic.dag`（单数），`pointcloud_motion` 的 conf 直接叫 `pointcloud_motion.pb.txt`，
  其余 3 个才叫 `<pkg>_config.pb.txt`。

## 2. 机制与数据流（精读代表①：pointcloud_preprocess）

`pointcloud_preprocess_component.cc` 的 `Init` / `Proc` 主干（本轮 read 全文）：

- **Init**（`:33-67`）：`GetProtoConfig` 读 dag 的 `config_file_path`（`:34-40`）→ 取
  `output_channel_name_` / `sensor_name_` / `lidar_query_tf_offset_`（`:42-48`）→ 读 `plugin_param`
  三段（`:50-53`）→ **`BasePointCloudPreprocessorRegisterer::GetInstanceByName(name)`** 取实现
  （`:54-55`，Registerer 通道，失败 `CHECK_NOTNULL` 直接崩 `:56`）→ `CreateWriter<LidarFrameMessage>`
  （`:58-59`）→ `InitAlgorithmPlugin`（`:61`）。
- **InitAlgorithmPlugin**（`:88-101`）：`SensorManager::GetSensorInfo` 查传感器内参（`:89-90`）→ 填
  `PointCloudPreprocessorInitOptions{sensor_name, config_path, config_file}` → `preprocessor_->Init`
  （`:92-96`）→ `lidar2world_trans_.Init(child_frame_id)` 初始化 TF 变换（`:99`）。
- **Proc**（`:69-86`）：收 `drivers::PointCloud` → `InternalProc` 成功才 `writer_->Write`（`:80-83`）。
- **InternalProc**（`:103-158`）：分配 `LidarFrame`/点云池（`:120-122`）→ 查
  `lidar2world` + `novatel2world` 位姿（`:130-135`，失败置 `PERCEPTION_ERROR_TF` 返回 false）→ 查外参
  `sensor2novatel_extrinsics`（`:141-145`）→ `cloud_preprocessor_->Preprocess(...)`（`:150-151`）。

**实现 `PointCloudPreprocessor`**（`preprocessor/pointcloud_preprocessor.{h,cc}`）是 Registerer 型算法，
无 plugins.xml，与组件编进同一个 `libpointcloud_preprocess_component.so`（lib 树已核）。实例级参数在
`data/pointcloud_preprocessor.pb.txt`（本轮 cat）：`filter_naninf_points` / `filter_nearby_box_points`
（车体前后左右 1.5/1.3/0.6/0.7 m 近区）/ `filter_high_z_points`（z>2.0）。**全 CPU，无模型、无 GPU。**

## 3. 注册与配置（精读代表②：map_based_roi 的两个插件 + 组件 vs 插件）

### 3.1 基类 `BaseROIFilter`（PluginManager 通道的证据）

`interface/base_roi_filter.h`（本轮 read 全文）：类 `BaseROIFilter`（`:37`）只 include
`cyber/plugin_manager/plugin_manager.h`（`:22`），**没有任何注册宏**——这是 PluginManager 型基类的标志

`Init(ROIFilterInitOptions)`（`:58-59`）、`Filter(ROIFilterOptions, LidarFrame*)`（`:69`）、`Name()`（`:76`）。

### 3.3 组件取实例：`PluginManager::Instance()->CreateInstance`

`pointcloud_map_based_roi_component.cc`（本轮 read 全文）：

- **Init**（`:26-70`）：读 conf → `output_channel_name_`（`:35`）→ `CreateWriter<LidarFrameMessage>`
  （`:36`）→ `SceneManager::Instance().Init()`（`:39`，全感知共享的场景管理器）→
  `use_map_manager_ = use_map_manager() && enable_hdmap()`（`:42-43`）→ map_manager 初始化（`:50`）→
  **`PluginManager::Instance()->CreateInstance<BaseROIFilter>(ConfigUtil::GetFullClassName(plugin.name()))`**
  （`:57-60`，短名 `HdmapROIFilter` 自动补 `apollo::perception::lidar::`）→ `CHECK_NOTNULL`（`:62`）→
  填 `ROIFilterInitOptions{config_path, config_file}` → `roi_filter_->Init`（`:63-66`）。
- **InternalProc**（`:84-115`）：map_manager 更新地图结构（`:88-95`）→ `roi_filter_->Filter(...)`；
  **关键回退**（`:102-111`）：`hdmap_struct == nullptr`（没地图）或 Filter 返回 false 时，
  `std::iota` 把 `roi_indices` 填成**全部点**——即「无地图 → 全点当 ROI，不报错、不过滤」。
  所以 `map_based_roi` 能不能真正裁 ROI，取决于地图是否加载成功。

### 3.4 组件编译 vs 插件加载（必做③）

| | 组件（5 个都是） | 算法实现 |
|---|---|---|
| 谁拉起 | `mainboard -d <dag>` / `cyber_launch`，按 dag 的 `module_library` + `class_name` 创建 | 被组件 `Init` 里取实例，不独立拉 |
| 注册 | `CYBER_REGISTER_COMPONENT`（写**非限定**类名，如 `pointcloud_preprocess_component.h:81`） | Registerer 用 `PERCEPTION_REGISTER_REGISTERER(Base*)`；PluginManager 用 `CYBER_PLUGIN_MANAGER_REGISTER_PLUGIN(类, Base*)` |
| 取实例通道 | — | ① Registerer：`Base*Registerer::GetInstanceByName(name)`；② PluginManager：`PluginManager::Instance()->CreateInstance<Base*>(GetFullClassName(name))` |
| .so 关系 | 独立组件 .so（lib 树：`libpointcloud_preprocess_component.so` 等，均有 `libDO_NOT_IMPORT_*` 伴生件） | Registerer 实现**同组件 .so 静态链入**；PluginManager 实现**独立 .so** + plugins.xml + 索引 |
| 本族分布 | 5 个全组件 | preprocess/ground/semantics/motion = Registerer；map_based_roi 的 roi_filter = **PluginManager（本族唯一）** |
| 失败表现 | dag 找不到类名 → mainboard 报错 | Registerer 失败 → `CHECK_NOTNULL` 崩（preprocess `.cc:56`）；PluginManager 失败 → `CHECK_NOTNULL` 崩（roi `.cc:62`） |

> 对照 02 篇：全 perception 的 PluginManager 型基类只有 5 个 base_class（14 条），其中
> `BaseROIFilter` 恰好只被本族 `pointcloud_map_based_roi` 的两个 ROI 插件使用。其余 4 个包与
> camera/radar/TL/fusion 一样走 Registerer（45 个基类之一）。

## 5. ⚠️ 本环境注意（必做④，本轮 `readlink -f` 实测）

1. **conf 落点：5 个 conf 全部在 profile 覆盖层**，`readlink -f` → `/apollo_workspace/profiles/ARCF_40P/modules/perception/<pkg>/conf/...`。
   但 **dag 落点混存**：`pointcloud_map_based_roi/dag/...` 在 **share 出厂件**
   `/opt/apollo/neo/share/...`，其余 4 个 dag 在 profile。改 conf 会写穿 profile、`buildtool build` 不覆盖；
   改 `/apollo_workspace/modules/perception/...`（① 层源码）**不重编绝不生效**。别假设 conf 一律指向 share（CLAUDE.md 口径已过期）。
2. **ground_detection 不需要 GPU / 推理**：包内**无 `.cu` 文件、conf 无 `use_gpu`、无任何模型**，两个检测器是纯 CPU 几何算法
   （spatio_temporal = 大/小网格 + 平面拟合 + 时序平滑，参数 `big_grid_size/small_grid_size/planefit_*` 全在
   `data/spatio_temporal_ground_detector.pb.txt`）。「感知跑不起来」别往 GPU 上归因，先看地图/上游 channel。
3. **semantics / motion 需要 GPU + 推理插件 + 模型**：两者 parser 各带 `pointwise_unet.cu`（CUDA kernel，本轮 ls），
   conf `use_gpu: true`、`infer_plugin: "MultiBatchInference"`（= 14 条插件里的 `onnx_multi_batch`，base_class
   `inference::Inference`）。模型同用 `pointwise_unet`（`data/*.pb.txt` 的 `info.name: "pointwise_unet"`）：
   semantics 用 `pointwise_unet_backbone.onnx + pointwise_unet_pfn.onnx`，motion 用
   `motion_backbone.onnx + motion_pfn.onnx`。**权重现状（对照 10 篇 §2.1）：`pointwise_unet` ✅ 有权重**（4 个 .onnx
   共 232 MB，落 profile）→ 预期可起；但 `libonnxruntime.so` 本机未找到（10 篇 §5），.onnx 实际多半经 TensorRT 解析，运行期待核。
4. **preprocess / ground / map_based_roi 无模型**：preprocess 是纯 CPU 裁剪；map_based_roi 依赖**高精地图**
   （`use_map_manager: true` + `enable_hdmap: true` → `MapManager`），不是模型。**地图没加载时 roi 不裁但也不报错**：
   `pointcloud_map_based_roi_component.cc:102-111` 回退「全点当 ROI」。排查「路外点没被滤掉」先
   `grep -n map_dir /apollo/modules/common/data/global_flagfile.txt | tail -1` 确认地图目录存在（10 篇 §7 分支 C）。
5. **本族 5 个组件 .so 全在**（`/opt/apollo/neo/lib/modules/perception/<pkg>/lib<pkg>_component.so`，本轮 ls），
   2 个 ROI 插件 .so 与索引条目也在；`grep -R`（**不是 `-r`**）搜 `/apollo/...` 才跟符号链接，避免假空。
6. 名字坑：组件名是 `PointCloudMapROIComponent` / `PointCloudGroundDetectComponent`（**不是** `MapBasedROI` /
   `GroundDetection`），dag `class_name` 写错 = mainboard 找不到类。
