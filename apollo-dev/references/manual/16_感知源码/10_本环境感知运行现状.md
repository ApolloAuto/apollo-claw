## 0. 一句话作用

回答一个问题：**本机 perception 现在能跑哪几条链、哪条一起就挂、挂在哪一步。**
本文只列现状与失效项，机制原理见 16_感知源码 其余各篇。全程只读，**未启动任何感知模块**，
所有「能起/不能起」都是**静态推断**（权重 + .so + conf 三者比对），不是实跑结论。

## 6. 缺陷清单（本轮逐条复核）

① **`camera_detection_bev` 整包未发布**：`src` 与 `include`、`lib` 三处都有，
`/opt/apollo/neo/share/modules/perception/camera_detection_bev` 与 `/apollo/modules/perception/camera_detection_bev` **不存在**
（比盘点表记的「只缺 dag」更严重：conf/dag 全没发布）→ 无法用 `/apollo/...` 绝对路径启动 BEV 检测；
要跑得先 `buildtool install perception` 后 `buildtool build -p modules/perception/camera_detection_bev` 补 install。

② **`lidar_output.launch` 未发布**：只在 `/opt/apollo/neo/src/modules/perception/lidar_output/launch/`；
share 与 ④ 层的 `lidar_output/` 只有 `conf`+`dag`（3 个聚合 dag 在）→ 想串行跑整条 lidar 链只能直接
`mainboard -d /apollo/modules/perception/lidar_output/dag/lidar_output.dag`，或用 §4 的 profile 聚合 launch。

③ **`outside_roi_filter` 有描述无库**：`/apollo/modules/perception/lidar_detection_filter/object_filter_bank/outside_roi_filter/plugins.xml:1-2`
声明 `liboutside_roi_filter.so`（`type=apollo::perception::lidar::OutsideRoiFilter`，`base_class=BaseObjectFilter`），
但 `/opt/apollo/neo/lib/.../outside_roi_filter/` 是**空目录**、`cyber_plugin_index` 无条目。
**当前无害**：生效档 `lidar_detection_filter/data/filter_bank.pb.txt` 启用的是
`ROIBoundaryFilter`/`StrategyFilter`/`SemanticFilter`/`BigmotRefineFilter`（`BackgroundFilter`、`MarkAreaFilter`、
`ObjectSplitFilter` 被注释），**没有引用 OutsideRoiFilter**；一旦把它写进 filter_bank 就会 `CreateInstance` 返回 nullptr。
（另注意 `data/background_filter.pb.txt:1` 有个同名字段 `outside_roi_filter_distance`，与该插件无关，别混。）

④ **TL 链 channel 拼写 `Retection`**：`traffic_light_detection/conf/traffic_light_detection_yolox_config.pb.txt`
的 `detection_output_channel_name:"/perception/inner/Retection"` 与
`traffic_light_recognition/dag/traffic_light_recognition.dag` 的 `channel: "/perception/inner/Retection"`
**两侧一致地拼错**（应为 Detection）→ **链路本身能通**，但 `cyber_channel -l` 里看到的是 `Retection`；
只改一侧 = 立刻断链。完整 TL 链：`front_12mm/image`（profile 只留 12mm）→ `/perception/inner/Detection`
→ `/perception/inner/Retection` → `/perception/inner/Tracking` → `/apollo/perception/traffic_light`。

⑤ **TL tracking 读 `/apollo/v2x/traffic_light`**：`v2x` 模块本环境已不存在（CLAUDE.md §5）→ 该输入永远无数据，
按 conf 里 `v2x_trafficlights_input_channel_name` 排查会白费功夫。

⑥ **`yolox_garbage_onnx` 是孤儿权重**（§2.1 末行）：profile 里放了 1.87 MB 的 .onnx，全树无 conf 引用。

## 7. 「感知没输出」排障树

先确认「输出」指哪条 channel：lidar 链终点 `/perception/lidar/detection_filter`→`lidar_tracking`；
融合终点 `/apollo/perception/obstacles`；TL 终点 `/apollo/perception/traffic_light`。
`cyber_channel -l` 看有无该 channel，`cyber_channel -e <ch>` 看内容（**`-w` 在本环境是坏的**）。

| 分支 | 典型现象 | 判定命令 | 结论/去处 |
|---|---|---|---|
| **A 模型缺失** | 进程起来后立刻退或日志报模型/权重文件打不开；`Init` 阶段失败 | ① 找出生效检测器：`grep -E 'name\|config_file' /apollo/modules/perception/<pkg>/conf/*_config.pb.txt`；② 顺着 `config_path`+`config_file` 打开 param 档取 `info.name`；③ `ls -la /apollo/modules/perception/data/models/<name>/`（**只有 BUILD+README = 没装；目录不存在 = §2.2 那 5 个**） | 装模型包 `apt-cache search perception-model` → `buildtool install perception-model-<名>`；或把 conf 换回有权重的检测器（§2、§3） |
| **B .so 缺失** | `mainboard` 报 `Failed to load library` / 组件根本没创建 | `grep module_library <dag>` 取相对路径 → `ls /opt/apollo/neo/lib/<该路径>`（**注意真实名常带 `_camera` 后缀，且同目录并存 `libDO_NOT_IMPORT_*.so`，dag 指的不是它**） | 没有 → `buildtool build -p modules/perception/<pkg>` 完成 install（`bazel build` 不算，运行时不读 `bazel-bin`） |
| **C 传感器 channel 无数据** | 组件在、日志无报错、下游 channel 一直空 | `grep -A2 readers <dag>` 取输入 channel → `cyber_channel -l \| grep <ch>`；`cyber_channel -e <ch>`；lidar 首级默认 `/apollo/sensor/velodyne64/compensator/PointCloud2`，相机 `/apollo/sensor/camera/camera_front/image`（`perception_all`）或 `front_6mm`（single_stage） | 驱动没起/相机名不匹配 → 查 profile 的传感器 conf；地图相关（`map_based_roi`、TL region_proposal）先按 `grep -n map_dir /apollo/modules/common/data/global_flagfile.txt \| tail -1` 确认地图目录存在 |
| **D conf 落点错** | 参数改了行为不变 | `readlink -f <改的文件>` —— 感知这边 conf/dag **大量指向 profile**（`ARCF_40P`），不是一律 share；改 `/apollo_workspace/modules/perception/...`（① 层）**不重编绝不生效** | 落 profile → 直接改立即生效；落 share → 下次 install 被覆盖 |
| **E 插件未注册** | 日志 `Class factory objs counts is 0` 或 `CreateInstance` 返回 nullptr，功能静默缺失 | `ls /opt/apollo/neo/share/cyber_plugin_index/ \| grep <关键词>`（perception 共 14 条，**全是 lidar 家族**；camera/radar/TL/fusion 分支本来就没有插件，找不到条目是正常的）；`cat <包>/plugins.xml` 核 `path` 指向的 .so 是否真在、`base_class` 是否写最顶层基类 | 典型命中 = `outside_roi_filter`（§6③）。插件改完必须 `buildtool build -p` 才进索引 |

**顺序建议**：A→B 是「起不来」，C→E 是「起来了没输出」。相机链在本机遇到「起不来」，
九成是 A（`3d-r4-half_caffe`）；lidar 链遇到「起不来」，先看是不是把 conf 换成了 pillars/cnnseg。

## 8. ⚠️ 本环境注意

1. **模型权重两个落点混用**：7 个目录的权重来自 `profiles/current`（人工/EDU 拷入，`buildtool` 不管），
   5 个来自 share 出厂件。判权重**一律看 ④ 层 `/apollo/modules/perception/data/models/`**，不看 src 树（src 树只有 16 个目录，无 `yolox_garbage_onnx`）。
2. **搜 `/apollo/...` 必须 `grep -R`**（`-r` 不跟随符号链接，会把「没人引用这个模型」误判成真）。
3. **「conf 里有这个检测器」≠「能用」**：本机同时存在三种失效形态——目录空（5 个）、目录不存在（5 个模型名）、
   插件 .so 缺（`outside_roi_filter`）。三种日志表现不同，别混。
4. **`perception_all` 与 `perception_lidar` 用的不是同一个 lidar 检测器**（cpdet vs center_point），排障时先确认走哪个 launch。
5. **8 个聚合 launch 是 profile 产物**，换 profile（`aem profile use <x>`）可能整套消失；包内只有 20 个子模块 launch。
6. 本文所有频率/有无数据类断言**均未运行验证**（本轮全程只读，未启动任何感知模块），标注为运行期待核。
