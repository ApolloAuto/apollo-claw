## 0. 一句话作用

TL 四子包是 PnC 红绿灯规则的**唯一观测来源**：`region_proposal → detection → recognition → tracking` 四级级联，
最终由 `traffic_light_tracking` 发 **`/apollo/perception/traffic_light`**（`apollo::perception::TrafficLightDetection`），
planning 的 traffic_rule / scenario 消费它判红绿灯。四级中间通道全是 `/perception/inner/*` 内部级联，PnC 不订。
本文件精读四级组件主干 + conf + 输出消息结构 + 模型依赖 + 4 个扩展点。

## 1. 四子包总表（①）

| 子包目录（`/opt/apollo/neo/src/modules/perception/…`） | 组件名（非限定） | 输入 channel | 输出 channel | 一句话职责 | 关键 conf | 取实例通道 |
|---|---|---|---|---|---|---|
| `traffic_light_region_proposal` | `TrafficLightsPerceptionComponent` | **dag 无 readers**，相机由 conf `camera_channel_names` 决定（profile 生效只有 `front_12mm`） | `proposal_output_channel_name = /perception/inner/Detection`（conf:17） | 按高精地图 signal + TF 外参投影出灯框 ROI，选相机 | `conf/traffic_light_region_proposal_config.pb.txt` | Registerer：`BaseTLPreprocessorRegisterer::GetInstanceByName`（.cc:124-126） |
| `traffic_light_detection` | `TrafficLightDetectComponent` | `/perception/inner/Detection`（dag:11） | `detection_output_channel_name = /perception/inner/Retection`（conf:7，**源码拼错**） | 灯框检测（yolox / caffe 两版 detector） | `conf/traffic_light_detection[_yolox]_config.pb.txt` | Registerer：`BaseTrafficLightDetectorRegisterer`（.cc:79-81） |
| `traffic_light_recognition` | `TrafficLightRecognComponent` | `/perception/inner/Retection`（dag:11） | `recognition_output_channel_name = /perception/inner/Tracking`（conf:12） | 灯色识别（efficient_net / caffe 三档） | `conf/traffic_light_recognition_config.pb.txt` | Registerer：`BaseTrafficLightRecognitorRegisterer`（.cc:78-80） |
| `traffic_light_tracking` | `TrafficLightTrackComponent` | `/perception/inner/Tracking`（dag:11）＋ `/apollo/v2x/traffic_light`（conf:7，v2x 侧） | `traffic_light_output_channel_name = /apollo/perception/traffic_light`（conf:6） | 多帧投票修正 + v2x 同步 + 转公开 proto | `conf/traffic_light_tracking_config.pb.txt` | Registerer：`BaseTrafficLightTrackerRegisterer`（.cc:116-118） |

四包全部走 **Registerer 通道**（实现与组件静态链进同一 .so，**无 plugins.xml、无 cyber_plugin_index 条目**），
与 lidar 家族的 PluginManager 通道相反。dag 的 `module_library`（.so 实名）：region_proposal =
`libtraffic_component_proposal.so`，detection = `libcomponent_traffic_light_detect.so`（yolox dag 同库），
recognition = `libcomponent_traffic_light_recognition.so`，tracking = `libcomponent_traffic_light_tracking.so`。

## 2. 组件主干精读（②）——Init/Proc 要点

四包内部消息载体统一是 `apollo::perception::onboard::TrafficDetectMessage`
（`common/onboard/inner_component_messages/traffic_inner_component_messages.h`，含 `camera::TrafficLightFrame`
+ `CarPose` + `stoplines_`）。detection / recognition 的 `Proc` 与 `InternalProc` 结构几乎逐行相同。

### 2.1 region_proposal（`Component<>`，**回调驱动，无 Proc**）

- 基类 `cyber::Component<>`（.h:47，**无模板参数**）——输入相机不在 dag 里声明，而在 `InitCameraListeners` 用
  `node_->CreateReader(camera_channel_name, 回调)` 手动订阅（.cc:182-199，逐相机 `:193-194`）。
- `Init()`（.cc:47-69）四步：`InitConfig → InitAlgorithmPlugin → InitCameraFrame → InitCameraListeners`。
- `InitConfig`（.cc:71-120）：`GetProtoConfig` 后把 `camera_names` / `camera_channel_names` 按逗号 `split`（:86-93）；
  取 `proposal_output_channel_name_`（:96-97）；`node_->CreateWriter<TrafficDetectMessage>`（:116-117）。
- `InitAlgorithmPlugin`（.cc:122-180）：`BaseTLPreprocessorRegisterer::GetInstanceByName`（:124-126）取 `TLPreprocessor`，
  `CHECK_NOTNULL`（:127）；`hd_map_ = HDMapInput::Instance()`（:168）+ `hd_map_->Init()`（:174）；另校验
  `camera_names_.size() == input_camera_channel_names_.size()`（:141-145），**两字段数量不一致直接 Init 失败**。
- 「Proc」实为 `OnReceiveImage`（.cc:226-317）：`CheckCameraImageStatus` 判相机存活 → `SyncInformation` →
  `VerifyLightsProjection`（:301，内部 `QueryPoseAndSignals` 查 map signal + `GenerateTrafficLights` 建灯 + 投影 ROI）→
  `traffic_detect_writer_->Write(preprocess_message)`（:314）。

### 2.2 detection（`Component<TrafficDetectMessage>`）

- `Init()`（.cc:29-42）→ `InitConfig` + `InitAlgorithmPlugin`。
- `InitConfig`（.cc:57-76）：`plugin_param` 三段拆出 `tl_detector_name_` / `config_path_` / `config_file_`（:64-67）；
  `CreateWriter(detection_output_channel_name)`（:73）。
- `InitAlgorithmPlugin`（.cc:78-94）：`BaseTrafficLightDetectorRegisterer::GetInstanceByName`（:79-81）+ `CHECK_NOTNULL`；
  `detector_->Init`（:88）。
- `Proc`（.cc:44-55）：`InternalProc` 成功才 `writer_->Write(message)`（:50-52）。
- `InternalProc`（.cc:96-102）：`detector_->Detect(message->traffic_light_frame_.get())`——**原地改 frame 的 traffic_lights**，
  不另建输出消息。

### 2.3 recognition（`Component<TrafficDetectMessage>`，与 detection 同构）

- `InitConfig`（.cc:56-75）：`plugin_param` 拆 `tl_recognitor_name_`（:63-66）；`CreateWriter(recognition_output_channel_name)`（:72）。
- `InitAlgorithmPlugin`（.cc:77-93）：`BaseTrafficLightRecognitorRegisterer::GetInstanceByName`（:78-80）。
- `InternalProc`（.cc:95-101）：`recognitor_->Detect(frame.get())`。`Proc`（:43-54）同上。

### 2.4 tracking（`Component<TrafficDetectMessage>`，唯一输出公开 proto 的一级）

- `Init()`（.cc:60-78）→ `InitConfig` + `InitAlgorithmPlugin` + `InitV2XListener`。
- `InitConfig`（.cc:91-113）：`v2x_trafficlights_input_channel_name_`（:98-99）；`plugin_param` 拆 tracker（:101-104）；
  **`CreateWriter<apollo::perception::TrafficLightDetection>(traffic_light_output_channel_name)`**（:108-109）——
  输出类型是公开 `TrafficLightDetection`，不是 `TrafficDetectMessage`。
- `InitV2XListener`（.cc:134-143）：`node_->CreateReader(v2x_trafficlights_input_channel_name_)`（:140-141）订 v2x 灯态。
- `InitAlgorithmPlugin`（.cc:115-132）：`BaseTrafficLightTrackerRegisterer::GetInstanceByName`（:116-118）。
- `InternalProc`（.cc:145-170）：`tracker_->Track(frame)`（:148）→ `SyncV2XTrafficLights`（:153）→
  `TransformOutputMessage`（:159）→ `writer_->Write(out_msg)`（:166）。
- `TransformOutputMessage`（.cc:279-408）：**多灯投票**（对 R/G/Y 分桶累加 confidence，取和最大的一盏灯 `max_light_id`
  :368-377，`swap` 到首位 :380-382）；每个 `TrafficLight` 写 `id` + `confidence` + `color` + `blink`（:388-393，取 `lights[0]` 的
  status）；`contain_lights = lights.size() > 0`（:396）。注意 `confidence=0` 的灯被降级为 `UNKNOWN`（:318-321 等）。
- `SyncV2XTrafficLights`（.cc:178-235）：v2x buffer 里按 `id` 匹配，`FLASH_GREEN→GREEN+blink`，直接覆写 `status.color/blink`。
  但 v2x 模块本环境已删 → buffer 恒空（见 §5）。

### 2.5 conf 三段式与实例级 conf

四包组件 conf 都只用一个 `plugin_param { name / config_path / config_file }` 指名实现（`config_path` 从 `perception/…` 起写，
见 02 篇 §3.3 拼路径规则）。生效选择（src 树出厂件原文）：

```protobuf
# region_proposal_conf:13-15  name:"TLPreprocessor"
# detection_conf:2-6         name:"TrafficLightDetection"      config_file:"detection_caffe.pb.txt"
# detection_yolox_conf:2-6   name:"TrafficLightTLDetectorYolox" config_file:"detection_yolox.pb.txt"
# recognition_conf:2-6       name:"EfficientNetRecognition"     config_file:"efficient_net.pb.txt"  （caffe 版 7-11 被注释）
# tracking_conf:1-5          name:"SemanticReviser"             config_file:"semantic.pb.txt"
```

实例级 conf（`data/*.pb.txt`，本轮 `nl -ba` 核，未走 read 工具故不引行号）：
`detection_caffe.pb.txt`（`info.name=tl_detection_caffe`，TensorRT，`baidu_iter_140000.caffemodel`）；
`detection_yolox.pb.txt`（`info.name=tl_detection_yolox`，Onnx，`infer_plugin=MultiBatchInference`，`yolox.onnx`）；
`recognition.pb.txt`（`vertical_caffe`/`quadrate_caffe`/`horizontal_caffe` 三档，各 TensorRT `baidu_iter_*.caffemodel`）；
`efficient_net.pb.txt`（`info.name=efficient_net`，Onnx，`efficient_net.onnx`，`outputs_cls` 4 类）；
`semantic.pb.txt`（**无模型**，只有 `revise_time_second:1.5` / `blink_threshold_second:0.55` / `hysteretic_threshold_count:1`）。

## 4. 模型依赖（④）

| 环节 | 生效档（profile `perception_trafficlight.launch`） | 模型目录 | 权重 | 落点 |
|---|---|---|---|---|
| detection | `traffic_light_detection_yolox.dag`（caffe 版 launch:7 被注释） | `tl_detection_yolox` | `yolox.onnx` 3.6 MB | profile |
| detection（备选） | `traffic_light_detection.dag`（caffe） | `tl_detection_caffe` | `baidu_iter_140000.caffemodel` 17.5 MB | **share 出厂** |
| recognition | `EfficientNetRecognition` | `efficient_net` | `efficient_net.onnx` 16 MB | profile |
| recognition（备选） | `TrafficLightRecognition`（caffe 三档） | `vertical_caffe`/`quadrate_caffe`/`horizontal_caffe` | 各 `baidu_iter_*.caffemodel` ≈1.6 MB | **share 出厂** |
| tracking | `SemanticReviser` | 无模型（纯时序规则） | — | — |

**结论**：TL 族 5 个模型目录（tl_detection_caffe / tl_detection_yolox / efficient_net / vertical / quadrate / horizontal）
**权重全齐、能跑**（对照 10 篇 §2.1/§3：TL 四级均判「预期可起」，依赖 map 的是 region_proposal）。与 lidar 链
cnnseg/pillars「有目录无权重」、camera 链 `3d-r4-half_caffe`「目录根本不存在」形成鲜明对比——TL 是本机感知里
**模型最完整的一条链**。

## 5. ⚠️ 本环境注意（⑤）

1. **TL 输入相机被 profile 改窄**：生效 conf（`/apollo/modules/perception/traffic_light_region_proposal/conf/…`，
   `readlink -f` → `profiles/ARCF_40P/…`）`camera_names:"camera_front_12mm"` + `camera_channel_names:"/apollo/sensor/camera/front_12mm/image"`
   ——**只一路 12mm**；出厂件（src conf:4-5）是 `front_6mm,front_12mm` 两路。注意 profile 连相机名都改成带 `camera_` 前缀
   （`camera_front_12mm`）。引 01 篇 §2.4。
2. **TL tracking 读 `/apollo/v2x/traffic_light`**（tracking conf:7，`.cc:140-141` 建 reader）：`modules/v2x` 本环境已不存在
   （CLAUDE.md §5）→ 该输入永远无数据，`SyncV2XTrafficLights` 的 v2x 覆写分支永不生效（buffer 恒空），
   按 `v2x_trafficlights_input_channel_name` 排查纯属白费。引 10 篇 §6⑤。
3. **conf 落点不统一**（本轮 `readlink -f` 实测）：`region_proposal` / `detection`（含 yolox）/ `recognition` 的 conf
   **在 profile 覆盖层** `/apollo_workspace/profiles/ARCF_40P/…`，而 `traffic_light_tracking` 的 conf **在出厂层**
   `/opt/apollo/neo/share/…`（下次 install 会被覆盖）。dag 落点：region_proposal / tracking 在 share，detection / recognition 在 profile。
   改 tracking 的 conf 建议改工作区源码副本 + 重编，否则被覆盖。
4. **`Retection` 源码原样拼错**：detection conf:7 输出 `/perception/inner/Retection`，recognition dag:11 读同一 `Retection`
   ——**两侧一致地拼错，链路能通**；只改一侧 = 静默断链。`cyber_channel -l` 里看到的是 `Retection`。完整链：
   `front_12mm/image → /perception/inner/Detection → Retection → Tracking → /apollo/perception/traffic_light`。
5. 搜 `/apollo/...` 必须 `grep -R`（`-r` 不跟随符号链接会假空）；TL 四包零插件，查不到 `cyber_plugin_index` 条目是正常的。

## 6. 修改与扩展点（⑥，4 个）

**① 新增灯色识别模型（新 Recognitor 实现）**
在 `traffic_light_recognition/recognition/<my_recog>/` 新建目录，写 `.h/.cc`，继承
`interface/base_traffic_light_recognitor.h` 的 `BaseTrafficLightRecognitor`，实现末尾加配套
`PERCEPTION_REGISTER_CLASS(BaseTrafficLightRecognitor, <name>)` 宏（该头文件 :68-69，宏名 `REGISTER_TRAFFIC_LIGHT_DETECTOR`
——识别与检测基类**同名宏**，靠基类类型区分）；挂进包 BUILD 的 `srcs`；`conf/traffic_light_recognition_config.pb.txt`
的 `plugin_param.name/config_file` 换成新实现 + `data/<my_recog>.pb.txt` 写模型 `info.name`。走 Registerer 通道，无 plugins.xml。

**② 新增 TL detector（新 Detector 实现）**
在 `traffic_light_detection/detector/<my_det>/` 新建目录，继承 `interface/base_traffic_light_detector.h` 的
`BaseTrafficLightDetector`，加 `PERCEPTION_REGISTER_CLASS(BaseTrafficLightDetector, <name>)`（该头文件 :67-68）；
挂 BUILD；把 `conf/traffic_light_detection_yolox_config.pb.txt`（或新建 conf + 新 dag）的 `plugin_param.name` 换成新实现。
`.so` 与组件同库（dag `module_library` 不变），改完 `buildtool build -p modules/perception/traffic_light_detection`。

**③ 只换模型 / 调参（不写代码）**
识别在 `EfficientNetRecognition`（onnx）与 `TrafficLightRecognition`（caffe 三档）之间切换 = 改
`recognition_config.pb.txt` 的注释块；检测在 yolox / caffe 之间切换 = 换 launch 里的 dag（或改 conf 的
`plugin_param`）。阈值调 `data/*.pb.txt`（如 yolox 的 `cls_th:0.24`、`nms_param.threshold:0.5`；recognition 的
`classify_threshold:0.5`）。注意 conf 落点（§5.3）：落 profile 直接改立即生效，落 share 改工作区副本 + 重编。

**④ 换 / 加 TL 输入相机**
改 `region_proposal` conf 的 `camera_names` 与 `camera_channel_names` **两个字段同时改**（`.cc:141-145` 校验数量一致，
不一致 Init 直接失败）；且相机名必须存在于 `sensor_manager`（`.cc:148` `IsSensorExist`，失败也 Init 失败）。
本车 profile 已只留 `camera_front_12mm`，要加回 6mm 需同时加 `front_6mm`（或 `camera_front_6mm`）两处。
