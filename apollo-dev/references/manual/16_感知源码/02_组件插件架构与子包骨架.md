## 0. 一句话作用

perception 的 31 个子包**不是 31 种架构，而是同一套骨架复制 31 次**：每个子包 = 1 个
`cyber::Component<T>` 外壳（读一路 inner message、算、写一路 inner message）+ `interface/` 里的
一个或几个 `Base*` 抽象类 + `conf/*.pb.txt` 里用 **`plugin_param` 三段式**指名要用哪个实现。
算法实现有两条取实例通道：**PluginManager（动态 .so，14 个，全属 lidar 家族）** 与
**PERCEPTION_REGISTER_REGISTERER（同 .so 内静态注册，camera/radar/TL/fusion 全走这条）**。
看懂 `lidar_detection` 一个包，其余 30 个只是换名字。上游 Component 机制见
[`../11_cyber框架/01_component与channel机制.md`](../11_cyber框架/01_component与channel机制.md)。

## 2. 子包同构骨架：目录 → 作用 → 必改点

代表包：`/opt/apollo/neo/src/modules/perception/lidar_detection/`（`ls -R` 全量核对）。

| 目录/文件 | 作用 | 必改点（二次开发） |
|---|---|---|
| `<pkg>_component.{h,cc}` | Component 外壳：`Init` 读 conf + 建 writer + 造算法实例；`Proc` 调 `InternalProc` 再 `Write` | 改输入消息类型 / 加第二路 reader（改模板参数 `Component<A,B>`）/ 改输出消息 |
| `interface/base_*.h` | **本包所有算法实现的抽象基类所在**（`base_lidar_detector.h`）。带 `PERCEPTION_REGISTER_REGISTERER` = Registerer 通道；只 include `plugin_manager.h` 而无注册宏 = PluginManager 通道 | 新增虚函数、扩 `InitOptions`；**新增算法时先在这里挑对基类** |
| `detector/`（或 `<算法>_bank/`、`roi_filter/`…） | 算法实现子目录，一算法一目录，各带自己的 `proto/model_param.proto` | 新增算法 = 新增一个平级目录 |
| `<算法>_bank/<impl>/plugins.xml` | 只有 **PluginManager 插件**才有；Registerer 实现没有 | 新插件必写 |
| `conf/<pkg>_config.pb.txt` | 组件级 conf：输出 channel、sensor_name、开关、`plugin_param{}` | 换算法、改输出 channel |
| `data/<算法>_param.pb.txt` | **算法实例级 conf**（模型名、阈值、预处理开关、嵌套 `plugins{}`） | 调参主战场 |
| `data/plugins/<plugin>.pb.txt` | 嵌套插件的实例级 conf | 调插件参数 |
| `proto/<pkg>_component_config.proto` | 组件 conf 的 schema（`plugin_param` 字段类型来自 `common/proto/plugin_param.proto`） | 加 conf 字段必须同步改这里 |
| `dag/<pkg>.dag` | 声明 `module_library`(.so)、`class_name`、`config_file_path`、`flag_file_path`、`readers{channel}` | **只声明输入**；换输入 channel 改这里 |
| `launch/<pkg>.launch` | 单 `<module>` 包住一个 `dag_conf` 绝对路径 + `process_name` | 单模块起停 |
| `BUILD` / `cyberfile.xml` | `apollo_package()`/`apollo_component`/`apollo_plugin`；`cyberfile.xml` 的 `<src_path>` 决定 install 落点 | 新增文件必须挂进 BUILD |
| `tools/offline_*.cc` | 离线单模块跑数据的 main | 可选 |
| `README.md` | 说明 | — |

`interface/` 覆盖面（现场 `ls */interface`）：31 包中 **22 个有 `interface/`**，共约 40 个 `Base*.h`；
`multi_sensor_fusion/interface/` 最多（8 个：`base_fusion_system` / `base_data_association` /
`base_gatekeeper` / `base_tracker` / `base_{motion,shape,type,existence}_fusion`），
`radar_detection/interface/` 9 个，`camera_tracking/interface/` 3 个。
全仓 perception 内 `PERCEPTION_REGISTER_REGISTERER` 出现 **45 次**（= 45 个 Registerer 型基类），
而 `CYBER_PLUGIN_MANAGER_REGISTER_PLUGIN` 只出现在 **14 个头文件**里 —— 与 `cyber_plugin_index` 的
perception 条目数 14 精确对齐（索引总数现 118）。

### 2.1 一帧数据流（lidar_detection 为例）

```
dag readers: /perception/lidar/pointcloud_ground_detection   （dag:9-11）
  → Component<LidarFrameMessage>::Proc(message)              （component.cc:70）
      → detector_->Detect(options, message->lidar_frame_)     （:87，实例由 conf 决定）
           └─ CenterPointDetection 内部再 CreateInstance<BaseDownSample>（center_point_detection.cc:112-114）
      → builder_.Build(...)  若 use_object_builder            （:95-101）
  → writer_->Write(message) 到 conf 的 output_channel_name    （:76 / conf:1 = /perception/lidar/detection）
```

## 3. 注册与配置

### 3.1 两条取实例通道（本节是理解 perception 的关键）

| | PluginManager 通道 | Registerer 通道 |
|---|---|---|
| 注册宏 | `CYBER_PLUGIN_MANAGER_REGISTER_PLUGIN(全限定类, 基类名)`（pcl_down_sample.h:74-75） | `PERCEPTION_REGISTER_REGISTERER(Base*)` + `PERCEPTION_REGISTER_<X>(实现)`（base_lidar_detector.h:84-86） |
| 描述文件 | **必须有 `plugins.xml`** | 无 |
| BUILD 规则 | `apollo_plugin(... description=":plugins.xml")` | 普通 `apollo_cc_library`，与组件同 .so |
| 取实例 | `PluginManager::Instance()->CreateInstance<Base>(ConfigUtil::GetFullClassName(name))` | `Base*Registerer::GetInstanceByName(name)` |
| .so 关系 | **独立 .so**，运行时按 `cyber_plugin_index` 动态加载 | 静态链进组件 .so，随组件一起加载 |
| 本环境数量 | 14（全 lidar 家族） | 45 个基类，camera/radar/TL/fusion/lane 全部 |
| 失败表现 | `CreateInstance` 返回 nullptr → 上层多为 `AINFO ... skipped` **静默降级** | `GetInstanceByName` 返回 nullptr → `CHECK_NOTNULL` 直接崩（component.cc:47） |

### 3.3 conf 三段式：`plugin_param { name / config_path / config_file }`

现场三个真实例证：

```protobuf
# ① 组件级：lidar_detection/conf/lidar_detection_config.pb.txt:1-9
output_channel_name: "/perception/lidar/detection"
sensor_name: "velodyne64"
use_object_builder: true
plugin_param {
  name: "CenterPointDetection"                      # 取 BaseLidarDetector 实现（Registerer 通道）
  config_path: "perception/lidar_detection/data"
  config_file: "center_point_param.pb.txt"
}
# ②（同文件 12-30 行）PointPillars / MaskPillars / CNNSegmentation 三段全被 # 注释 —— 换算法即换注释

# ③ 组件级：lidar_detection_filter/conf/lidar_detection_filter_config.pb.txt:1-7
plugin_param { name: "ObjectFilterBank" config_path: "perception/lidar_detection_filter/data"
               config_file: "filter_bank.pb.txt" }   # ObjectFilterBank 本身不是插件，它去读 filter_bank 再造插件

# ④ 算法实例级里的嵌套插件：lidar_detection/data/center_point_param.pb.txt:75-79
plugins { name: "PclDownSample" config_path: "perception/lidar_detection/data/plugins"
          config_file: "pcl_down_sample.pb.txt" }
```

**拼路径的确切规则**（`util.cc:64-86` + `GetFilePathWithEnv`）：

```
config_path 相对 → "modules/" + config_path        →  modules/perception/lidar_detection/data
              → 逐个试 $APOLLO_CONF_PATH（实测 = /apollo）前缀，第一个存在的即返回
最终文件 = GetAbsolutePath(上一步, config_file)
  = /apollo/modules/perception/lidar_detection/data/center_point_param.pb.txt
```

即 **`config_path` 里不写 `modules/` 前缀、不写 `/apollo`**，只从 `perception/...` 开始写；
`config_file` 只写文件名。模型权重是另一套：`GetModelPath(model_info.name())` 走
`$APOLLO_MODEL_PATH`（实测 `/apollo/modules/perception/data/models`），
`center_point_param.pb.txt:3-16` 的 `info.name: "center_point_paddle"` + `proto_file`/`weight_file`
→ `/apollo/modules/perception/data/models/center_point_paddle/centerpoint.pdmodel`。

**顺序即启用**（`object_filter_bank.cc:36-56`）：`filter_bank.pb.txt` 的 `plugins` 列表顺序 = filter 执行顺序，
注释掉一段 = 该 filter 不启用。**profile 层与包内不同**（现场 diff）：

| 层 | 启用的 filter |
|---|---|
| 包内 `/opt/apollo/neo/src/...`（10 行） | `ROIBoundaryFilter`, `StrategyFilter` |
| profile `/apollo_workspace/profiles/ARCF_40P/...`（运行时真正生效，35 行） | `ROIBoundaryFilter`, `StrategyFilter`, `SemanticFilter`, `BigmotRefineFilter`（`BackgroundFilter` / `MarkAreaFilter` / `ObjectSplitFilter` 被注释） |

### 3.5 为什么 camera / radar / traffic_light / fusion 「零插件」

不是没有可换实现，而是**它们全走 Registerer 通道**：conf 的 `plugin_param` 三段式写法一模一样，但取实例用
`Base*Registerer::GetInstanceByName`，实现与组件编在同一个 .so 里，因此既不需要 `plugins.xml`，
也不会出现在 `cyber_plugin_index`。证据（grep 线索，行号未 read 故不引）：
`camera_detection_multi_stage/camera_detection_multi_stage_component.cc` 用
`BaseObstacleDetectorRegisterer::GetInstanceByName(plugin_param.name())`（conf 里 name 为
`YoloObstacleDetector` / `Yolox3DObstacleDetector`）；`multi_sensor_fusion_component.cc` 用
`BaseFusionSystemRegisterer`，`probabilistic_fusion.cc` 再用 `BaseDataAssociationRegisterer` /
`BaseGatekeeperRegisterer`；`multi_sensor_fusion/interface/` 8 个基类里**只有 3 个带 `PERCEPTION_REGISTER_REGISTERER`**（`BaseFusionSystem`/`BaseDataAssociation`/`BaseGatekeeper`），另 5 个（`BaseTracker`/`Base{Existence,Motion,Shape,Type}Fusion`）是裸接口、由 `PbfTracker` 硬编码 `new`（`pbf_tracker.cc:76-105`）——**换 fusion 的 tracker 实现必须改源码重编，不是 conf 可换**（2026-09-08 由 08_fusion 篇实测修正）。
**一处例外**：camera 的 `detector/yolox3d/yolox3d_obstacle_detector.cc` 里
`CreateInstance<inference::Inference>(...)` —— camera 分支自身不注册插件，但**消费** lidar 侧那个
`onnx_multi_batch` 推理插件。

## 4. 修改与扩展点（4 个）

**① 新增一个感知插件（PluginManager 型，如再加一种 ObjectFilter）**
1. 选对 `Base*`：在目标包 `interface/` 或 `common/interface/` 找**最顶层**基类；只有 §3.2 那 5 个
   base_class 是插件化的，其余（如 `BaseLidarDetector`）属 Registerer 通道，走 ②。
2. 新建目录 `/apollo_workspace/modules/perception/lidar_detection_filter/object_filter_bank/my_filter/`
   （先 `buildtool install perception-lidar-detection-filter` 把包源码拉进工作区），写 `.h/.cc`，
   头文件末尾 `CYBER_PLUGIN_MANAGER_REGISTER_PLUGIN(apollo::perception::lidar::MyFilter, BaseObjectFilter)`。
3. `plugins.xml`：`<library path="modules/perception/.../my_filter/libmy_filter.so">` +
   `<class type="apollo::perception::lidar::MyFilter" base_class="apollo::perception::lidar::BaseObjectFilter">`。
   属性名只有 `type`/`base_class`/`path`（无 `class_type`）。
4. `BUILD` 用 `apollo_plugin(name="libmy_filter.so", description=":plugins.xml", ...)`，**不要手写 `cc_library`**。
5. 挂到 conf：`filter_bank.pb.txt` 加一段 `plugins { name: "MyFilter" config_path: "perception/lidar_detection_filter/data" config_file: "my_filter.pb.txt" }` —— 短名即可，`GetFullClassName` 自动补 `apollo::perception::lidar::`。
6. `buildtool build -p modules/perception/lidar_detection_filter`（必须 install 才被索引；见 §5）。

**② 新增一个 Registerer 型算法实现（camera/radar/TL/fusion/lidar detector）**
在包内新建 `detector/my_det/`，继承 `interface/base_*.h`，实现末尾写该基类配套的
`PERCEPTION_REGISTER_<X>(MyDet)`（如 `PERCEPTION_REGISTER_LIDARDETECTOR`，见
`base_lidar_detector.h:85-86`），加进包 `BUILD` 的 `srcs`（同一 .so，需 `alwayslink` 语义由
`apollo_component`/`apollo_cc_library` 保证），然后把 conf 的 `plugin_param.name` 改成 `MyDet`。

**③ 新增一个感知组件（新子包）**

## 5. ⚠️ 本环境注意

1. **插件索引不扫 `bazel-bin`**：`APOLLO_PLUGIN_SEARCH_IN_BAZEL_OUTPUT=0`（实测）。真实索引在
   `APOLLO_PLUGIN_INDEX_PATH=/opt/apollo/neo/share/cyber_plugin_index`（118 条，perception 14 条）。
   只 `bazel build` 出的 .so 运行时**看不见**，必须 `buildtool build -p <包路径>` 完成 install。
2. **`APOLLO_PLUGIN_DESCRIPTION_PATH=/apollo_workspace:/opt/apollo/neo` 而 `APOLLO_PLUGIN_LIB_PATH=/opt/apollo/neo/lib`**：
   plugins.xml 优先读工作区、.so 只从 install 树取 → 可能「描述新、库旧」。
3. **conf 落点先 `readlink -f`，别假设指向 share**：现场 `lidar_detection/conf/*.pb.txt`、
   `lidar_detection_filter/{conf,data}/*` 均指向 `/apollo_workspace/profiles/ARCF_40P/...`（profile 覆盖层），
   而 `lidar_detection/dag/lidar_detection.dag` 指向 `/opt/apollo/neo/share/...`（出厂件）。
   **同一个包里 conf 在 profile、dag 在 share 是常态**；感知 8 个聚合 launch 全在 profile 层。
4. **`outside_roi_filter` = 有描述、无实现**：`/opt/apollo/neo/src|share/.../object_filter_bank/outside_roi_filter/`
   **只有 `plugins.xml` 一个文件**（声明 `OutsideRoiFilter` / `BaseObjectFilter` / `liboutside_roi_filter.so`），
   无 `.h/.cc/BUILD`；`include/` 与 `lib/` 下同名目录存在但**空**；`cyber_plugin_index` 无条目。
   现场核对包内与 profile 两份 `filter_bank.pb.txt` 均**未引用**它（`background_filter.pb.txt:1`
   的 `outside_roi_filter_distance` 只是参数名，不是插件引用）——补齐盘点 §3.3 的待核项。
   若手工写进 conf：`CreateInstance` 返回 nullptr → `object_filter_bank.cc:44-46` 只打 AINFO 后 `continue`，
   **静默少一个 filter，不报错**。
5. **模型权重缺 5 个**（现场重核 `/apollo/modules/perception/data/models/`，17 目录 / 12 有权重）：
   `cnnseg128_caffe`、`cnnseg16_caffe`、`cnnseg64_caffe`、`point_pillars_torch`、`mask_pillars_torch`
   **只有 `BUILD`+`README`** → conf 把 `plugin_param` 换成 `CNNSegmentation` / `PointPillarsDetection` /
   `MaskPillarsDetection` 会「起来但检测不出东西 / Init 失败」。补装：`apt-cache search perception-model`
   → `buildtool install perception-model-<名>`。默认生效的是 `CenterPointDetection`（权重齐）。
6. **搜 `/apollo/...` 用 `grep -R`**（`-r` 不跟随符号链接，会假空）。
7. `grep` 命中 ≠ 已核：本文对只 grep 未 read 的文件（camera/fusion 组件 .cc）**只写路径不写行号**。
