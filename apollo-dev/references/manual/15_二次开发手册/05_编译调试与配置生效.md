## 0. 一句话作用

本篇是**通用开发闭环**：拉源码 → 改 → 编 → 装 → 起 → 看 → 回滚，以及一条可机械执行的
**「改了没生效」判定链**。具体插件类型的六件套与 pipeline 写法见
[01](./01_新增TrafficRule.md) / [02](./02_新增Scenario与Stage.md) / [03](./03_新增Task.md) /

## 2. 编译产物落点：`buildtool build` 到底做了什么

**它不是 `bazel build` 的别名。**`core/task/bazel/build.py:191-195`（本轮 read）拼出并**依次执行两条命令**：

```
bazel run <公共参数> dev/buildtool/mock:mock_install_src -- <install_prefix>   # :191-192、:197
bazel run <公共参数> dev/buildtool/mock:mock_install     -- <install_prefix>   # :194-195、:207
```

- `install_prefix` = `get_config("base","apollo_root") + "/"`（`:174-175`）= **`/opt/apollo/neo/`**
  （`config/module.conf:30 apollo_root=/opt/apollo/neo`，grep 实测）。`--compatible-with-src` 只在第二条追加（`:178-179`）。
- 这两个 target 所在的 `dev/buildtool/mock/BUILD` 是**每次 build 现生成的**
  （`core/task/bazel/__init__.py:83-118`：`install()` / `install_src_files()` 各把本次要编的包展开成
  `<pkg>:install` / `<pkg>:install_src` deps）。本机现存文件（read 实测）里只有
  `//modules/planning/traffic_rules/region_speed_limit:install{,_src}` —— 即**上次 build 的目标**，可当"上次编了什么"的证据。
- 任一条返回非 0 → `ErrCode.BazelErr` "Compiling and install failed!"（`:198-215`）。
- 产物落 `/opt/apollo/neo/{lib,include,share,src}`；`share/cyber_plugin_index/` 本轮实测 **118 条**
  （CLAUDE.md 记 113，已过期，以 2026-09-08 实测为准）。

**`bazel-bin` 运行时不读**：`mainboard` 找 `.so` 只用 `APOLLO_LIB_PATH=/opt/apollo/neo/lib`
（02 篇 §2.4），插件索引只看 `APOLLO_PLUGIN_INDEX_PATH`，且 `APOLLO_PLUGIN_SEARCH_IN_BAZEL_OUTPUT=0`（env 实测）。
顺带纠一条：CLAUDE.md 说「`bazel-bin` 下只有 `dev` 一项」**已过期**，本轮 `ls` 实测 4 项
（`_solib_local dev external modules`）—— 但这不改变结论：**有 `bazel-bin` 产物 ≠ 运行时能看见**。

## 3. 「改了没生效」判定链（本篇核心）

按顺序做，每步都有判定命令；任一步不满足就停在那步修。

| 步 | 问题 | 判定命令 | 期望输出 / 判读 |
|---|---|---|---|
| **0** | 我改的文件到底在哪一层？ | `readlink -f <你改的文件>` | 输出 `/apollo_workspace/profiles/{current,ARCF_40P}/...` → **profile 覆盖层**（改对了，长期驻留）；输出 `/opt/apollo/neo/share/...` → **出厂件**（生效但下次 install 被覆盖）；输出 `/apollo_workspace/<sp>/...`（非 profiles）→ **①层源码副本，不重编就不生效**；`readlink -f` 与输入同路径 → 不是软链，就是这个文件本身 |
| **0′** | 我改的是不是**根本没被读**的那一份？ | `ls -l /apollo/<sp>/conf/`（一次看全目录箭头） | ④ 层 `/apollo/...` 才是进程真正读的入口（`APOLLO_CONF_PATH=APOLLO_FLAG_PATH=APOLLO_DAG_PATH=/apollo`）。本机 ④ 层软链 **374 指向 profiles/current、339 指向 share**（02 篇 §3.1），**别按模块名猜** |
| **1** | 改的是哪一类东西？ | 见下表 | 决定要不要重编 |
| **2** | 需要 `buildtool build` 吗？ | 见下表「需重编」列 | 需要就 `cd /apollo_workspace && buildtool build -p <包相对路径>` |
| **3** | 装进去了吗？（只对代码/插件） | `ls /opt/apollo/neo/lib/<sp>/`；`ls /opt/apollo/neo/share/cyber_plugin_index/ \| grep <包目录名>`；`ls -l --time-style=+%F_%T` 看 mtime | `.so` 存在**且 mtime 是刚才**；插件还必须有索引条目。缺任一 → 只 `bazel build` 了 / build 失败 / `cyberfile.xml` 的 `<src_path>` 与目录不一致 |
| **4** | 进程重启了吗？ | `pgrep -a mainboard` | 改 conf/dag/pipeline/gflags **一律要重启该组件**（无热加载）。老进程还在 = 你看的是旧配置 |
| **5** | 进程真的读到了你那份文件吗？ | `grep -R 'use dag conf\|use module library\|use config file\|use flag file' /apollo/data/log/ \| tail` | 日志里直接打印解析后的绝对路径（`module_controller.cc:58/:85`、`component_base.h:79/:89`，02 篇 §1）。路径与你改的文件不符 → 回步 0 |
| **6** | 值真的变了吗？ | `cyber_channel echo <输出channel>` / 你自己在代码里加的 `AINFO` | 仍是旧值且步 5 路径正确 → 字段名/message 名写错（proto text 解析对未知字段静默或报警） |

### 3.1 分类型速查（步 1–2）

| 改的东西 | 生效条件 | 需重编 | 备注 |
|---|---|---|---|
| ④ 层 conf（`*.pb.txt`、`*.conf`） | 改软链写穿到落点 + **重启组件** | ❌ | 落点 profile 层最好；share 层会被下次 install 覆盖 |
| ④ 层 dag（`readers`/`interval`/`class_name`） | 重启组件 | ❌ | timer 组件（control/canbus）dag 里没有 readers，改订阅得改代码/flag |
| gflags **值**（写进模块 `.conf`） | 重启组件 | ❌ | 优先级：同文件后行覆盖前行 > 模块 conf 覆盖 `global_flagfile` > `.cc` DEFINE 默认值（02 篇 §3.2） |
| gflags **新增一个 flag** | 改 ①层 `*_gflags.cc` **和** `.h` 两处 | ✅ | 只改 `.cc` → 别处 `extern` 不到 → undefined symbol |
| pipeline / 清单（`traffic_rule_config.pb.txt`、`public_road_planner_config.pb.txt`、control `pipeline.pb.txt`） | 改**生效档**（`readlink -f` 判） + 重启 | ❌ | **书写顺序 = 执行/优先级顺序**；planning scenario 是 first-match |
| `.cc` / `.h` 业务代码 | `buildtool build -p` + 重启 | ✅ | — |
| `plugins.xml` / 注册宏 / `BUILD` | `buildtool build -p` + 重启 | ✅ | 索引条目由 install 生成，见步 3 |
| `.proto` | `buildtool build -p`（且依赖方也要重编） | ✅ | — |
| `cyberfile.xml` | `buildtool build -p` | ✅ | `<src_path>` 改错 → install 落错位置，步 3 直接暴露 |
| ①层 `/apollo_workspace/<sp>/conf/*` | `buildtool build -p` 后才进 ④ 层 | ✅ | 只想调参就别动这里，动 ④ 层软链 |

## 4. 常见编译/链接/加载错误对照表

| 症状 | 原因 | 修法 |
|---|---|---|
| 运行期 `Class factory objs counts is 0`（so 编出来了但里面没注册对象） | BUILD 用 `cc_library` 代替 `apollo_plugin` → 少 `alwayslink=True`，注册宏的静态对象被链接器裁掉 | 换 `apollo_plugin(name="lib*.so", description=":plugins.xml", ...)`，**不要手写 `alwayslink`** |
| `CreateInstance` 返回 nullptr / 插件从不执行 | `plugins.xml` 的 `base_class` 写了中间基类，或属性名误写 `class_type`（合法只有 `path`/`type`/`base_class`） | `base_class` 一律写**最顶层基类**全名（`apollo::planning::{Task,Stage,Scenario,TrafficRule,Planner,PncMapBase}`、`apollo::control::ControlTask`） |
| 链接期 undefined symbol `FLAGS_xxx` / 某函数 | 新 flag 只加了 `.h` 没加 `.cc` 的 `DEFINE_*`；或 BUILD `deps` 漏了提供该符号的库 | `.cc`+`.h` 同改；补 `deps` |
| bazel 直接 `fail`：proto target 名不合规 | `proto_library` 的 `name` **必须以 `_proto`/`proto` 结尾**（`tools/proto/proto.bzl:119-121`，04 篇 §2 步2 read 核） | 改名，并且 **C++ 侧依赖写去掉尾 `_proto` 再加 `_cc_proto`** 的别名（`proto.bzl:129-134`）：`x_conf_proto` → `//...:x_conf_cc_proto` |
| `buildtool build -p <路径>` 报找不到包 / install 落错地方 | `cyberfile.xml` 的 `<src_path>` 与目录不一致（它同时决定 install 位置与 bazel package 路径） | 改成 `//` + 目录相对工作区路径 |
| 新建的包 buildtool 完全"看不见" | buildtool 扫工作区**遇到第一个含 `cyberfile.xml` 的目录就停止下钻** | 别把新包嵌在别的包内部，平级放 |
| `buildtool info <pkg>` 崩 `TypeError: a bytes-like object is required, not 'list'` | 本环境缺陷（`core/package_identification/identifier.py:113`，buildtool 9.0.0-rc1-r19） | 直接读 `/opt/apollo/neo/share/packages/<pkg>/cyberfile.xml` |
| dag 起不来：`no module library ... found!` | `module_library` 写的是**相对 `/opt/apollo/neo/lib` 的路径**，且必须已 install | 步 3 核 `.so`；别写 `bazel-bin` 路径 |
| dag 起不来且无更多日志 | dag 的 `class_name` 与 `CYBER_REGISTER_COMPONENT(X)` 注册的**非限定名**不一致 → `CreateClassObj` 返 nullptr → mainboard return false | 逐字对齐 |
| conf 改了"静默用默认值" | planning task 的实例 conf 路径 = `scenarios/<sc>/conf/<stage.name 小写>/<task.name 小写>.pb.txt`，文件名取 **pipeline 里 `name` 别名的小写**（只 tolower，不驼峰转下划线）；control 的 conf 文件名固定 `conf/controller_conf.pb.txt` | 见 03 / 04 篇；日志里搜 `Failed to load` / `Load ... config file successfully` |

## 5. 调试闭环

```bash
# ① 单模块前台起（首选）：日志走 glog，本机 GLOG_alsologtostderr=0 → 想打屏临时置 1
GLOG_alsologtostderr=1 mainboard -d /apollo/modules/planning/planning_component/dag/planning.dag
# ② 一组 dag
cyber_launch start /apollo/modules/planning/planning_component/launch/planning.launch
cyber_launch stop  /apollo/modules/planning/planning_component/launch/planning.launch
```

**日志**：落 `/apollo/data/log/`（env `GLOG_log_dir=/apollo/data/log`，另 `global_flagfile.txt:10 --log_dir=/apollo/data/log`
双写同一值）。本机实测 **364 个文件 / 9.5 G**，每个模块一组 `<proc>.INFO`（软链到最新）+
`<proc>.log.INFO.<时间>.<pid>`。级别与开关**本机由 GLOG 环境变量控制**（`env | grep -i glog` 实测）：
`GLOG_minloglevel=0`、`GLOG_alsologtostderr=0`、`GLOG_colorlogtostderr=1`、`GLOG_max_log_size=500`(MB)。
临时调：`GLOG_minloglevel=0 GLOG_v=4 GLOG_alsologtostderr=1 mainboard -d <dag>`。
本机 profile 层的 conf 里**没有** `--minloglevel` / `--v=` 行（grep 实测），所以别去 conf 里找。

**看数据**（工具参数见 11/03 篇）：`cyber_channel list` → `type <ch>` → `info <ch>`（writer/reader 必须同时在）
→ `hz <ch>` → `echo <ch>` / `bw <ch>`；一屏 `cyber_monitor`。**`-w/--window` 全坏，别用**。
`cyber_channel -e` 是 `echo` 的等价短写、`-l` 是 `list` 的等价短写（沿用 01/04 篇写法）。

**录包回放**：`cyber_recorder record -a -k <大channel> -o my.record`（`-c` 白名单 / `-k` 黑名单，
录点云前务必排大户）→ `cyber_recorder info my.record` 看 channel/消息数/时间范围 →
`cyber_recorder play -f my.record -l -k <自己要产出的 channel>`（黑名单掉自己的输出，避免自我干扰）→
`cyber_channel hz <自己输出>` 确认闭环。抠段：`cyber_recorder split -f 原包 -o 小包 -b <起> -e <止>`。

## 6. 回滚与清理

**改动前先备份**（一行成本，省一次翻车）：
```bash
f=/apollo/modules/planning/planning_component/conf/planning.conf
cp -L "$f" "$(readlink -f "$f").bak.$(date +%F_%H%M)"   # -L 抓软链内容，备份写到落点旁边
```

| 想回滚什么 | 怎么做 | 代价 |
|---|---|---|
| profile 层被我改坏的 conf/dag | 从 `.bak` 拷回；或从出厂件拷：`cp /opt/apollo/neo/share/<sp>/conf/<f> $(readlink -f /apollo/<sp>/conf/<f>)` | 无 |
| share 层出厂件被我改过 | `buildtool reinstall <pkg>` 把出厂件覆盖回来（**实现未 read，先在非关键包上试**） | 会覆盖该包全部 install 产物 |
| 整个 profile 想换回默认 | 本机 `/apollo_workspace/profiles/` 有 `ARCF_40P`(current) / `ARCF_40P_NDT` / `sample`；切换用 `aem profile`（本轮未验，别在车上首试） | 全车配置整体切换 |
| 我编的包想退回官方版本 | `buildtool reinstall <pkg>`；彻底一点再 `buildtool clean -p <包相对路径>` 清该包 release cache | 见下 ⚠️ |
| 磁盘被日志吃满（本机 9.5 G） | `find /apollo/data/log -name '*.log.*' -mtime +7 -delete`（先 `-mtime +7 \| wc -l` 看数量）；`.INFO` 软链留着 | 丢历史日志 |

**⚠️ `buildtool clean` 不是无痛操作**（`clean.py` 全文 read）：不带参数它就会
① `bazel clean --expunge`（`:68`，清整个 bazel 输出根）；
② **删除** `apollo.bazelrc`、`.bazelrc`、`tools` 三项（`:77-81`，判据是 `exists() or is_symlink()`
——本机 `.bazelrc` 是 **4642 B 的普通文件**，一样被删）；
③ 删除 `third_party/`、`modules/` 下**所有软链**（`:83-90`，本机 `third_party` 有 23 个软链）；
④ `rm -rf dev/bazel`（`:92-94`）。
加 `-e` 还会遍历 `/opt/apollo/neo/packages/*`，删每个包的 `local/` 目录并把 `latest` 重指到版本号最大的那个（`:96-100`、`:135-150`）。
`-p <相对路径>` 则只清指定包的 release cache（`:102-122`，**不接受绝对路径**，`:177-181` 直接报错）。
`setup.sh`（全 16 行 read）**只重建 `.env`/`.workspace.json`/`.buildtool.conf` 三个软链，不重建 `.bazelrc` 与 `tools`** ——
本机 `tools -> /opt/apollo/neo/packages/bazel-extend-tools/latest/src` 与 `third_party/*` 软链的
mtime 都等于最近一次 build 时刻（`Sep 8 15:35`，与 `dev/buildtool/mock/BUILD` 同刻），
说明它们由 **build 的 preprocess 阶段重建**（`core/task/bazel/handler/preprocess.py:379` 附近处理
`bazel-extend-tools`，本轮仅 grep 定位，**完整重建路径待核**）。**结论：`clean` 之后必须重新 `buildtool build`
才能恢复可编译状态，别在赶时间时随手 clean。**

## 7. ⚠️ 本环境注意

- **只 `bazel build` 等于没做**：运行时只认 `/opt/apollo/neo/{lib,share}` 的 install 产物，插件索引不扫 `bazel-bin`（`APOLLO_PLUGIN_SEARCH_IN_BAZEL_OUTPUT=0`）。`bazel-bin` 里有新 `.so` 也白搭。
- **改 share 出厂档会被下次 install 覆盖**；改 profile 覆盖层不会被覆盖，但 **profile 目录不进包的版本管理** —— 要提交的配置改动必须落 ①层 `/apollo_workspace/<sp>/conf/` 并 `buildtool build -p`，然后再确认 ④ 层软链落点没把它盖掉。
- **`APOLLO_PLUGIN_DESCRIPTION_PATH=/apollo_workspace:/opt/apollo/neo`（两个前缀，首个命中即返回）**，而 `APOLLO_PLUGIN_LIB_PATH=/opt/apollo/neo/lib`（一个）→ 可能出现「描述文件读工作区新版、`.so` 还是 `/opt` 旧版」的错配。改了 `plugins.xml` 又没 install 成功时，症状会很怪（类名/基类对不上）。判据：两边文件都 `ls -l` 看 mtime。
- **搜 `/apollo/...` 必须 `grep -R`**（`-r` 不跟随软链，整棵 ④ 树返回空，极易误判"没人引用"）。
- **`/apollo/scripts/<模块>.sh` 与 `buildtool bootstrap start` 大半不适用**（拼死路径）；launch 一律 `cyber_launch start <绝对路径>`，dag 一律 `mainboard -d <绝对路径>`。
- 无热加载：conf/dag/pipeline 改完**必须重启组件**，`cyber_launch` 也没有 `restart`。
- `buildtool` 多数子命令启动即联网刷索引；离线环境下先确认这一步不会卡死。
