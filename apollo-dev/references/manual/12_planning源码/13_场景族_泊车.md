## 0. 一句话作用

泊车是 planning 里唯一「**不走参考线、靠 open_space 算法库直出轨迹**」的场景族。本机生效注册 13 个
scenario 里的泊车类有 **3 个**：`VALET_PARKING_PARK`（注册序第 3，走新 `_PARK` 开放空间链，最完整）、
`PARK_AND_GO`（第 11，起步脱困，借用**旧 provider 链**）、`FREE_SPACE`（第 12，profile 新增，纯旧链）。
另有 4 个泊车相关 scenario **装了未注册**（`valet_parking` 旧包 / `precise_parking` / `large_curvature` /
`square`），加进 `public_road_planner_config.pb.txt` 即启用、不用重编（04 篇 §5）。开放空间算法库本体与
两条 task 链的机制见 [10 篇](10_planning_open_space.md)，scenario/stage 框架见 [04](04_scenario框架.md)/
[05](05_stage框架.md) 篇，本文只写「泊车族怎么组合它们」。

### 2.3 泊车 stage 怎么用 `_PARK` 链（引 10 篇 §2.1 + 本轮 pipeline 核对）

Stage 2/3 的 6 个 task（pipeline :70-93 / :99-122，两 stage 相同）就是 10 篇 §2.1 的**新 `_PARK` 链**：

```
OPEN_SPACE_REPLAN_DECIDER → OPEN_SPACE_ROI_DECIDER_PARK → OPEN_SPACE_PATH_PLANNING
→ OPEN_SPACE_TRAJECTORY_OPTIMIZER_PARK → OPEN_SPACE_TRAJECTORY_POST_PROCESS
→ OPEN_SPACE_FALLBACK_DECIDER_PARK
```

与旧 provider 链的差别（10 篇 §2.1）：新链把**混合 A\*** 拆进 `OpenSpacePathPlanning`（`HybridAStar` 新构造
只吃 `WarmStartConfig`）、把**热启动 + 距离逼近(OBCA) + 迭代锚定平滑**拆进 `OpenSpaceTrajectoryOptimizerPark`；
旧链两步都藏在 `OpenSpaceTrajectoryProvider` 内部。`OPEN_SPACE_ROI_DECIDER_PARK` 是 `_PARK` 专用（旧
`OPEN_SPACE_ROI_DECIDER` 那份实例 conf 因此变孤儿，§5.3）。**当前 `OPEN_SPACE_TRAJECTORY_OPTIMIZER_PARK`
没有任何生效实例 conf**——两个 stage 目录里都没有 `open_space_trajectory_optimizer_park.pb.txt`，OBCA 权重
（`weight_{steer,a,x,y,phi,v...}`、`max_speed_forward/reverse` 等）全落
`tasks/open_space_trajectory_optimizer_park/conf/default_conf.pb.txt`（引 10 篇 §3.3/§4①）。

### 2.4 PARK_AND_GO 概述（起步脱困）

- **IsTransferable**（park_and_go_scenario.cc:53-118）：要求 `lane_follow_command`（:55-58）+ 参考线（:59-62）+
  routing 终点 `end_lane_way_point`（:81-85）；最终条件是 :112-116 —— 车速 < `max_abs_speed_when_stopped` 且
  距终点 > `scenario_config.min_dist_to_dest()` 且（`GetNearestLaneWithDistance` 找不到 lane / lane 不在 lane 上 /
  非 `CITY_DRIVING` 类型）。
- **stage 链**（pipeline :1-120）：前 3 个 stage（CHECK/ADJUST/PRE_CRUISE）**都跑旧 provider 链**
  （`OPEN_SPACE_ROI_DECIDER` + `OPEN_SPACE_TRAJECTORY_PROVIDER` + `OPEN_SPACE_TRAJECTORY_PARTITION` +
  `OPEN_SPACE_FALLBACK_DECIDER`，pipeline :5-20/:26-41/:47-62）——用于把车从非标准停车位/路外**挪回车道**；
  最后一个 `PARK_AND_GO_CRUISE`（:64-120）切回常规 on-lane 12 task + `SMOOTH_STOP_TRAJECTORY_FALLBACK`
  （含 `ST_BOUNDS_DECIDER`、`RSS_DECIDER`），正常巡航。stage 间靠 next_stage_ 跳（具体过渡未逐 stage read，
  待核，见 §7 ②）。

### 2.5 FREE_SPACE 概述（纯旧链）

- **IsTransferable**（free_space_scenario.cc:57-129）：`custom_command` 存在且 `Is<FreeSpaceCommand>`（:59-64）→
  `UnpackTo(context_.free_space_command)`（:66-69）→ 车静止（:70-77）→ 用命令里的 `parking_spot_pose` 构
  `end_box`（:78-88）→ `drivable_roi` 必须逆时针（:100-104）、ego/end 两框都被 `drivable_roi` 包含（:105-109）、
  `non_drivable_roi` 必须顺时针（:110-121）且与两框无碰撞（:122-126）→ true。
- **stage 链**（pipeline :1-17）：单 stage `STAGE_FREE_SPACE`，只有 3 个 task：
  `OPEN_SPACE_TRAJECTORY_PROVIDER` + `OPEN_SPACE_TRAJECTORY_PARTITION` + `OPEN_SPACE_FALLBACK_DECIDER`
  （**没有 ROI_DECIDER**——可行驶区由命令里的 `drivable_roi` 直接给定）。

## 4. 修改与扩展点（4 个）

**① 加一个泊车 stage**（挂进 valet_parking_park）：照 `stage_parking_park.cc` 抄 `Process` + `ExecuteTaskOnOpenSpace`
+ `next_stage_` 写法，.h 尾加 `CYBER_PLUGIN_MANAGER_REGISTER_PLUGIN(..., Stage)`，class 加进同包 `plugins.xml`
（base_class 写 `apollo::planning::Stage`），pipeline 加 `stage{}` 块，上游 stage 的 `next_stage_` 指向它别名；
`buildtool build -p modules/planning/scenarios/valet_parking_park`。

**② 加一个泊车 task**：
```bash
buildtool create --template planning_task modules/planning/tasks/my_park_task --class_name MyParkTask
buildtool build -p modules/planning/tasks/my_park_task
```
`plugins.xml` 的 `base_class` 必须写 `apollo::planning::Task`；把 `task{name:"MY_PARK_TASK" type:"MyParkTask"}`
插进 ④ `valet_parking_park/conf/pipeline.pb.txt` 对应 stage（顺序=执行顺序）；实例 conf 放
`conf/valet_parking_parking_park/my_park_task.pb.txt`。

**③ 调 OBCA 权重：先建文件，别改死配置**。当前 `OPEN_SPACE_TRAJECTORY_OPTIMIZER_PARK` 无实例 conf（§2.3），
距离逼近权重/迭代锚定平滑参数要么新建
`/apollo/modules/planning/scenarios/valet_parking_park/conf/valet_parking_parking_park/open_space_trajectory_optimizer_park.pb.txt`
（文件名=别名小写，两个 stage 目录都要，或只建真正在用的），要么改
`/opt/apollo/neo/share/modules/planning/tasks/open_space_trajectory_optimizer_park/conf/default_conf.pb.txt`
（会被下次 install 覆盖）。改前先 `readlink -f` 认落点。

**④ 换地图 / 换库位**：生效 `--map_dir` 只认 `global_flagfile.txt` **最后一行**（dreamview 选图 append，引 15 篇 §5），
任何 planning conf 都别写 `--map_dir`；换图后在 dreamview 同步/选图，或直接给当前地图加 `parking_space` 元素。
库位 id 必须是地图 `base_map` 里真实存在的（§5.1）。

## 5. ⚠️ 本环境注意

1. **泊车必须有地图库位，否则场景永远进不去**：`IsTransferable` 靠参考线 `parking_space_overlaps()` 找
   `parking_spot_id`（valet_parking_scenario.cc:92-98 / :115-126），失败只 AINFO 返 false。本机生效地图
   `/apollo/modules/map/data/apollo_virutal_map/` 的 `base_map.txt` 有 **8 处 `parking_space`**，抽到 4 个库位
   id `451089043`–`451089046`（引 10 篇 §5.5）→ 下泊车指令时 `parking_spot_id` 必须填这几个真实 id 之一。
2. **下泊车指令走 external_command 的 `valet_parking_command`**（引 14_数据与消息/04）：Service
   `/apollo/external_command/valet_parking`（ValetParking processor 已注册）→ 内嵌算路 → 发
   `/apollo/planning/command` 的 `PlanningCommand.parking_command`；`ValetParkingCommand` 必填
   `parking_spot_id`（valet_parking_command.proto:22），**没有 end_pose**。命令 `header.timestamp_sec` 要新（2s
   超时丢弃）、`command_id` 只记最后一条。自写客户端照 `planning_command.py` 的 valet_parking client。
