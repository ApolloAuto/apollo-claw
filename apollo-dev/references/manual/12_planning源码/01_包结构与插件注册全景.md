## 5. ⚠️ 本环境注意

1. **判断符号存不存在必须搜两棵树**：`planning_interface_base` 的 5 个基类头文件**只在 `include/` 树**，src 侧连 `.h` 都没有（只有 proto）。「在 src 里 grep 不到 Task/Planner」是安装形态导致的，不是被删。
   ```bash
   grep -rn "class Task" /opt/apollo/neo/src/modules/planning/ /opt/apollo/neo/include/modules/planning/
   ```
2. **④ 层 conf/dag 落点必须 `readlink` 判定，不要假设一律指向 share**（CLAUDE.md 此处已过期）。本轮实测 `/apollo/modules/planning` 子树 **412 个符号链接 = 127 指向 `/apollo_workspace/profiles/current/...`（profile 覆盖层）+ 285 指向 `/opt/apollo/neo/share/...`（出厂件）**。关键的 `public_road_planner_config.pb.txt`、`traffic_rule_config.pb.txt`、`planning.conf`、`planning.dag` **都是 profile 版**；`planning.launch`、navi 三件套是出厂版。
3. **改 conf 与改源码生效路径不同**：改 ④ 符号链接 = 写穿到落点、**立即生效**（重启模块即可）；改 ① `/apollo_workspace/modules/planning/...` 的 conf 副本**不生效**，必须 `buildtool build -p <包路径>` 完成 install。
4. **插件索引不扫 `bazel-bin`**（本机 `APOLLO_PLUGIN_SEARCH_IN_BAZEL_OUTPUT=0`）。真实索引在 `/opt/apollo/neo/share/cyber_plugin_index/`（planning 70 条）。只 `bazel build` 出 `.so` 运行时看不见 —— **必须 `buildtool build` 走完 install**。
5. **搜 `/apollo/...` 用 `grep -R` 不是 `-r`**：`-r` 不跟随符号链接，planning 的 conf/dag 全是链接，`-r` 会返回假空。
6. **两个包要改先 install**：`planning_base`、`planning_interface_base`（后者即使 install，`.cc` 也不可得）。
