## 0. 一句话作用

本文件讲两件事：**① 先纠正一个口径**——11.0 里**没有名为「借道」的 scenario**，「借道/借道绕行」是
**task 层**（`LaneBorrowPath` / `LaneBorrowPathGeneric`，已在 [06](06_task框架与task大族.md) §2.3 列过），
「绕行」跨 scenario 由 traffic_rule（`KEEP_CLEAR` / `REFERENCE_LINE_END` 等，见 [07](07_traffic_rule框架.md)）与 task
共同实现，**不构成 scenario 族**；② 把**路口 / 红绿灯族** 6 个场景里与「信号灯 + 路口」强相关的 4 个
（BARE_INTERSECTION_UNPROTECTED、TRAFFIC_LIGHT_UNPROTECTED_LEFT_TURN、TRAFFIC_LIGHT_UNPROTECTED_RIGHT_TURN、
TRAFFIC_LIGHT_PROTECTED）做成清单 + 1 个代表精读 + 规则交叉引用。链路位置：Planner（[03](03_planners_public_road.md)）
→ Scenario → Stage → Task，选场景 = first-match（[04](04_scenario框架.md) §2.2）。

## 1. 「借道 ≠ scenario」事实澄清（必读）

- **11.0 的 scenario 注册表（`public_road_planner_config.pb.txt` 生效档 13 条）里没有任何「借道/绕行」类场景**：
  `ls /opt/apollo/neo/src/modules/planning/scenarios/` = 19 个子包，名字带 borrow/avoid 的**一个都没有**（[03](03_planners_public_road.md) §3.2 全表）。
- **借道 = task**：`tasks/lane_borrow_path`（`LaneBorrowPath`）与 `tasks/lane_borrow_path_generic`（`LaneBorrowPathGeneric`），
  都是 `PathGeneration` 子类（[06](06_task框架与task大族.md) §2.3），沿道借相邻车道避障；「借道决策」由
  `PathDecider` 等路径决策 task 触发。**它们不是场景，不参与 first-match**。
- **绕行 = traffic_rule + task 混合**：`KEEP_CLEAR`（不阻塞路口）与 `REFERENCE_LINE_END`（参考线终点处理）在
  traffic_rule 层按交规改写参考线（[07](07_traffic_rule框架.md) §3.1 顺序表），避障的横向绕行则落在 task 链的
  `OBSTACLE_NUDGE_DECIDER` / `LANE_BORROW_PATH` / `LANE_CHANGE_PATH`。
- **为什么路口族 pipeline 里能看到 `LANE_BORROW_PATH`**：它只是该 stage 的 task 列表成员（见 §3.2 实测），
  说明「借道」作为 task 在红绿灯族内也照跑——**别因此误以为路口族里有个「借道 scenario」**。
- 结论：查「借道/绕行怎么改」→ 去 [06](06_task框架与task大族.md) 的 `lane_borrow_path*`、[07](07_traffic_rule框架.md) 的
  `keepclear`/`reference_line_end`；查「路口/红绿灯怎么进」→ 本篇。

## 3. 代表精读：TRAFFIC_LIGHT_UNPROTECTED_LEFT_TURN（③）

### 3.1 `IsTransferable`（`traffic_light_unprotected_left_turn_scenario.cc:60-142`，全 209 行 read）

判定链（早退 false + 累积 bool）：

1. `planning_command->has_lane_follow_command()`（:62）→ `other_scenario==nullptr || refline 空`（:65）→
   `FirstEncounteredOverlaps()` 空（:71-73）。
2. 遍历首遇 overlap：先遇 `STOP_SIGN` 或 `YIELD_SIGN` → **直接 false**（:76-78）；遇 `SIGNAL` 记下并 break（:79-81）。
   没有 SIGNAL → false（:84-86）。**注意：这是「红绿灯场景优先于停/让」的显式互斥**。
3. 从 `reference_line().map_path().signal_overlaps()` 取同一信号灯组：以首遇 SIGNAL 的 `start_s` 为基准，
   把 `|Δs| ≤ 2.0m`（`kTrafficLightGroupingMaxDist`，:95）的所有灯收进 `next_traffic_lights`（:96-101）。
4. 遍历该组每盏灯（:104-126）：距离 `overlap.start_s - adc_front_edge_s` 不在 `(0, start_traffic_light_scenario_distance(5.0m)]`
   内就 continue（:112-115）；用 `frame.GetSignal(overlap.object_id).color()` 取**感知给的灯色**，
   **只要有一盏非 GREEN 且非 BLACK（即 RED/YELLOW/UNKNOWN）→ `traffic_light_scenario = true`**（:121-124，注释
   "need iterate all lights to check no RED/YELLOW/UNKNOWN" :103）。
5. `turn_type = reference_line_info.GetPathTurnType(...)`，**必须 == `hdmap::Lane::LEFT_TURN`**（:131-135），否则 false。
6. 通过则把该组灯 id 写进 `context_.current_traffic_light_overlap_ids`（:136-139）→ return true。

**精读要点**：
- **「进不进红绿灯 scenario」只由距离 + 灯色（非绿/黑）决定**，不查「是否受保护」；受保护与否是
  PROTECTED vs UNPROTECTED 两个不同 scenario 的分野（见 §3.4）。
- 灯色来自 `frame.GetSignal(id)`（Frame 侧缓存了感知 `TrafficLightDetection`，来源见 §5），**不是地图信号灯状态**。
- **信号灯组匹配 = 距离分组（2.0m 内同组）**，不是按 overlap 对象一对一，这是左转多灯路口的关键细节。
- `Enter`（:152-206）把同组灯 id 写进 `planning_status.traffic_light().current_traffic_light_overlap_id`（:195-204），
  供 rule / stage 停车用；`Exit`（:144-150）`Clear()` 该状态。

### 3.2 stage 链与跳转（pipeline 3 条 + stage 内 next_stage_）

`conf/pipeline.pb.txt`（全 147 行 read）3 个 stage，**task 完全同构（11 个）**：LANE_FOLLOW_PATH → **LANE_BORROW_PATH** →
FALLBACK_PATH → PATH_DECIDER → RULE_BASED_STOP_DECIDER → ST_BOUNDS_DECIDER → SPEED_BOUNDS_PRIORI_DECIDER →
SPEED_HEURISTIC_OPTIMIZER → SPEED_DECIDER → SPEED_BOUNDS_FINAL_DECIDER → PIECEWISE_JERK_SPEED。
**src 出厂版没有 `fallback_task`**（与 [05](05_stage框架.md) §3.2 的 pull_over 出厂档一致）。

## 4. 路口相关 traffic_rule 交叉引用（④）

注册顺序即执行顺序（`traffic_rule_config.pb.txt` 生效档 11 条，[07](07_traffic_rule框架.md) §3.1）：

| rule（注册#） | 何时起效 | 机制（已核） |
|---|---|---|
| `STOP_SIGN`（#7） | 每条参考线每周期都跑 `ApplyRule`；地图 overlap 是 STOP_SIGN 且场景未处理时 | 造虚拟停车墙（[07](07_traffic_rule框架.md) §2.2 手法）；conf `stop_distance 1.0` |
| `TRAFFIC_LIGHT`（#8） | **同 STOP_SIGN，全周期全参考线跑**（traffic_light.cc:51-56 `ApplyRule` → `MakeDecisions`） | 遍历 `signal_overlaps()`，已 `done_traffic_light_overlap_id`（场景写回）跳过（:89-100）；`frame->GetSignal(id).color()` **非 GREEN 且非 BLACK 且 `stop_deceleration ≤ max_stop_deceleration(4.0)`** → `BuildStopDecision(..., STOP_REASON_SIGNAL, stop_distance 2.25)`（:144-166）。**红灯停车由这个 rule 兜底**，即使没进 TL scenario 也会停 |
| `YIELD_SIGN`（#9） | 全周期跑；地图 overlap 是 YIELD_SIGN | 造虚拟停车墙；conf `stop_distance 1.0` |
| （邻接）`KEEP_CLEAR`（#4） | 全周期跑 | 不阻塞路口（Junction 内清空），与路口族交叉（[07](07_traffic_rule框架.md) §3.1） |

**关键关系**：scenario 只负责「进红绿灯场景、蠕行、过口巡航」，**红灯下该不该停、停在哪由 `TRAFFIC_LIGHT` rule 兜底**；
scenario 的 `Exit` 把灯 id 写回 `done_traffic_light_overlap_id`（traffic_light.cc:89-100 读它跳过），形成
「场景处理完 → rule 不再重复停」的闭环。`STOP_REASON_SIGNAL=100`（红灯）/ `YELLOW_SIGNAL=107`（黄灯）见
[14_数据与消息/05](../14_数据与消息/05_PnC解题常用消息字段速查.md) §6 的 `StopReasonCode`。

## 5. ⚠️ 信号灯输入与「能起但没输出」真相（⑤）

- **灯色来源链**：感知 TL 四级（region_proposal → detection → recognition → tracking）→
  `/apollo/perception/traffic_light`（`apollo::perception::TrafficLightDetection`）→ planning 的 `Frame::GetSignal(id).color()`
  取 `traffic_light(0)` 的 `color`。字段契约（`color` :41 / `id` :44 / `confidence` :47 / `contain_lights` :64）见
  [16_感知源码/06](../16_感知源码/06_交通灯族.md) §3 与 [14_数据与消息/05](../14_数据与消息/05_PnC解题常用消息字段速查.md) §2。
- **本机 TL 链模型权重齐、能跑**（[16/06](../16_感知源码/06_交通灯族.md) §4 实测：`tl_detection_yolox` / `efficient_net` 等
  权重全在，四级均「预期可起」），但 **`perception_all.launch` 的 4 个前/后视相机检测 dag 中的 2 个（`_front`/`_rear`）
  因 `3d-r4-half_caffe` 模型目录不存在而预期直接失败**（[16/10](../16_感知源码/10_本环境感知运行现状.md) §2.2/§3），
  后接的 estimation/refinement/tracking 空转 → **相机链（含 TL region_proposal 依赖的相机）整体起不来**。
  → 想让 TL 有输出，先解决相机检测模型；TL 单独链路可用 `perception_trafficlight.launch`（走 yolox + efficient_net）。
- **first-match 优先级**：BARE(#4) 在 TL 三兄弟(#7-9) 之前，但 BARE 自排「带信号灯路口」，所以带灯路口落 TL 族；
  **排 `LANE_FOLLOW`(#13) 之后的场景永不生效**（[04](04_scenario框架.md) §5）。
- **conf 落点坑**：路口族 4 个 scenario 的 conf 生效档都在 **profile 覆盖层**（`readlink -f` 判定，别改 share）；
  `TRAFFIC_LIGHT` rule 的 conf 也 → profile（[07](07_traffic_rule框架.md) §3.3 逐包 `ls -l` 结论）。
- **已装未注册差集 6 个**里本族相关仅 `precise_parking`（泊车）；路口族 4 个**全部注册**（[03](03_planners_public_road.md) §3.2）。
